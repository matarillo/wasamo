# T9 レトロスペクティブ

T9 は iteration grammar の **オーナー human-visible smoke**（ADR evidence
item 6 の owner 半分）。T8 のアシスタント baseline（6 frame 陽性対照）とは
別ゲートで、screenshot baseline では代替できない人間目視の承認である

rollback の registry leak（finding #4）を修正したため、T9 は最終的に
**test-only Rust + 1 件の production fix** を含む（詳細は
[../implementation/log.md](../implementation/log.md) の 2 件の
review-remediation entry）。

start gate / end gate（frame-by-frame の claim↔pixel 照合表 / items 5–7）は

## 目標・前提・計画仮説の再点検

### 観測された事実（反証可能な signal）

- owner 採取 8 frame、count 推移 **6→9→5→0→1→6** が各クリックに連動。
  frame 5（Clear 後 `NEW #0`）が member-live の単一フレーム対照。
  narrowing / scrolldown で WrapPanel reflow / ScrollView も被覆。→
  collection 駆動 cardinality を可視に証明（静的ツリー再現不能）。
- **別エージェントレビュー round 1** が end gate の 2 点を指摘：① `Clear`
  行の過大主張（直接テスト無し、compositional ＋ owner-smoke のみ）、②
  evidence/README が T9 owner-run 未記載。
- owner 元指示の seam 機構 `#[cfg(test)] + pub(crate)` は **compiler で
  反証**：integration test crate から `#[cfg(test)]` 項目は不可視（実 widget
  挿入＝integration test 必須で unit 化も不可）。
- **別エージェントレビュー round 2** が **finding #4**（production バグ）を
  発見：commit-failure rollback 枝が未 commit staged を後始末せず leak。
  `rg "impl Drop for WidgetNode"` = 0 件で `Drop` 不在を裏取り。初版 rollback
  テストはこれを**検出できていなかった**（木形のみ assert）。
- seam の release 不在を **compiler probe で反証**（非 gated 参照が
  `--release` で `E0425`、`cargo rustc --release --print cfg` に
  `debug_assertions` 無し）。最終的に全テスト green（8 integration / 403 lib
  / workspace / release build）。

### 自己分析（どの層が外れたか）

- **owner 元指示の機構層（seam = `#[cfg(test)]`）:** これは私でなく owner
  指示の誤りだが、実装着手前に compiler で反証し surface できた（spike
  規律の適用）。撤回 → B 案合意。ここは機能した。
- **テスト設計層（最大の外れ）:** 在フェーズ close で rollback テストを
  書いた際、**「木形が戻る」を 4 点契約の証明と取り違え、資源（registry）
  状態を assert しなかった**。テスト対象の枝が実際に leak していたのに、
  テスト自身がそれを通す half-proof。T7（branch matrix を代表型で閉じた）→
  T8（prose↔pixel の不整合）→ T9（テスト主張↔資源状態）と、根（close
  artifact を ground truth に突き合わせていない）は同じまま層を変えて再発。
- **被覆判断層（軽微）:** `Clear` を当初 compositional 被覆で足りると判断
  （round 1 指摘）。direct テスト化で解消。

### 計画仮説・前提の問い直し（オーナーと）

- **「T9 はアシスタント無 Rust の owner 目視ゲート」** — 部分反証。本体は
  そうだが、再レビュー＋owner 決定で test-only Rust + production fix が
  入った。二段ゲート（T8 baseline / T9 owner smoke）の設計自体は item 6
  どおり機能。
- **「proof gap は T10 へ carry すればよい」** — 反証（owner 決定）。runtime
  テストは doc-close で片付かないため**在フェーズ close**。half-proof を
  carry で先送りしない方針を owner が明示。
- **「fault seam は owner 指示どおり `#[cfg(test)]`」** — 反証（compiler）。
  → owner 決定で `debug_assertions`（B 案）。
- **「`Clear` は compositional ＋ owner-smoke で十分」** — 反証（round 1）。
  → direct テスト 2 本（handler unit + integration）。
- **「rollback テストは木形で契約を満たす」** — 反証（round 2 / finding
  #4）。→ registry baseline まで assert、production も staging 枝と対称化。

### 反証可能な是正テスト

- **owner-smoke の frame 自己反証:** 各 frame の主張を実 pixel と 1:1 照合
  してから accept を記録（end gate 表で実施）。
- **plan の mid-phase 乖離 cross-check:** T0 凍結 list を着手時に最新 owner
  決定と突き合わせ、乖離は work around せず revise（plan T9 の 4-form 改訂）。
- **defensive-branch テストの資源契約 assert（finding #4 由来・新規）:**
  失敗/rollback 枝のテストは observable な木形だけでなく**資源状態
  （registry/binding が pre-write baseline に戻る）まで assert** する。観測
  不能分（handler-free 生成子は registry entry を持たない）は log に明示
  disposition し、proven な兄弟枝との code symmetry に帰着させる。
- **兄弟失敗枝の cleanup 対称性レビュー（finding #4 由来・新規）:** 同種の
  失敗パスが複数枝あるとき（staging 失敗 / commit 失敗）、後始末コードが
  対称か（build 済み child を全て `widget_destroy`）を枝間 diff で確認する。
