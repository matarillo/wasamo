## Main Learning

中心的な学びは「**T3 で確定した accept boundary が T4 の lowering
形を**ほぼ自動的に決めた**」こと。T3 retro で書いた構造 —
「`check_expr_type` は default で reject、accept 側 (Box.aspect /
Box.fill) が opt-out する」— のおかげで T4 の `lower_expr` には
context 引数も Box-specific 分岐も要らなかった: Ratio / Color の
arm はそのまま `IrLiteral::Ratio` / `IrLiteral::Color` を返すだけで
よく、「ここに到達したのは accept だったから」という invariant を
T3 が引き受けている。

これは "boundary を check 側に寄せる" 設計の利点として明示できる。
代替設計 (lower 側が `(enclosing_widget, prop_name)` を参照して
"これは Box.aspect / Box.fill か?" を再確認する) を採ると、lower が
不要に check の責務を背負う / 同じ判定が 2 箇所に散る。今回の責務
分割では:

- check: positional validity + value validity (zero-side reject) +
  const-only contract。
- lower: 構造変換のみ。値の意味的妥当性は再確認しない。
- ir_loader (T7): runtime 側 defense-in-depth。`wasamoc` 以外から
  作られた IR にも 2+ children / positional reject をかける。

この三段構成が「surface (check) → AST (lower) → IR (loader)」の
責任分割として綺麗に並んだ。T8 の layout は IR 側に乗るので、また
別の責務 (numeric resolver) を担う — 仕様検証ではない。

副次的な学びとして、**lowering を「単純な structural translation」
として保つ規律** が今回も発火した。一見、lower 側で
`if num <= 0 || den <= 0 { ... }` を再確認する魅力はあるが、これを
やると T8 layout 側でも同じ防御を書きたくなり、結局 invariant の
所有者が増える。今回の panic コメントを「正規 reject 後の
defense-in-depth」と書き換えたのは、その規律を明文化する意図。

T5 (`wasamoc` IR text emit) に持ち越した境界:

- T4 で `IrLiteral::Ratio` / `IrLiteral::Color` が IR に乗ったので、
  T5 はその IR variant を surface form (`<num>:<den>` / `#RRGGBB`
  または `#RRGGBBAA`) として emit する作業。dsl_spec §8.2 の
  `RATIO` / `COLOR` トークン形に整える。
- alpha = 0xFF のときに `#RRGGBB` で出すか `#RRGGBBAA` で出すかは
  T5 で決まる選択 (round-trip 識別性 vs 短縮表記)。T1 emitter は
  まだ未定。round-trip 試験 (T10) でどう assert するかと一緒に
  決める。
