## Main Learning

中心的な学びは Phase 1 T1 で確立した「**設計が既に閉じている spelling
は T1 内で書く / 構造変更が必要なものは stub に留める**」という分割が
Phase 2 でもそのまま適用できる、という確認。今回の case は更に明快で、
DD-M3-P2-002 / 003 の Option A variant strategy が「`PropertyValue` を
広げない / `WASAMO_VALUE_*` を入れない / `HandlerExpr` を触らない」を
明示しているため、T1 の編集面積はほぼ「`IrLiteral` への 2 variant 追加
+ 既存 2 箇所の exhaustive match arm + テスト」だけに収束した。stub
(`unimplemented!`) が一切要らない step になっており、これは T2 以降
(parser / check / lower / ir_loader) が IR variant を直接消費する場所
で初めて新規構造を要求するから。

副次的な学びとして、`wasamo-runtime::ir_loader` の literal 系周辺関数が
`parse_literal` も `extract_*` も既に catch-all で書かれているため、
Phase 2 の新規 literal を追加する段では下流 stub が必要ない、という
事実が Phase 1 retro の予言通り成立した。T7 で catch-all を正規 arm に
昇格させる流れは Phase 1 T5 (bool 用) と同じ形でよい。

color packing (`0xAARRGGBB`) の emit ヘルパは `wasamoc::emit` と
`wasamo-runtime::ir_loader::render_lit` の両方に重複している。T5 の
ラウンドトリップ整備時に共通化を検討するが、現状は両 crate に
`wasamo-ir` 由来の表現以外の依存関係がなく、helper を切り出すと逆に
crate 跨ぎの公開面が増えるため、T1 では重複を許容している。

## Follow-Up

T1 から後続 task への明示的な引き渡し:

- **T2 (wasamoc lexer / parser):** `<num>:<den>` (`RatioLit`) と
  `#RRGGBB` / `#RRGGBBAA` (`ColorLit`) のトークン化と AST 化。
  `wasamoc::emit_literal` の Ratio / Color arm は T1 で
  spelling-correct に書き終わっているので、T2 は emit を上書きせず
  lexer / parser / `Expr::*` 側を増やすだけでよい。
- **T3 (wasamoc check):** `bind aspect:` / `bind fill:` を
  attribute 名で reject、`num <= 0 / den <= 0` を rejected side を
  名指しで reject、Box 多子を ZStack/VStack/HStack 推奨 diagnostic で
  reject。
- **T4 (wasamoc lowering):** `Expr::RatioLit` →
  `IrLiteral::Ratio { num, den }`、`Expr::ColorLit` →
  `IrLiteral::Color(u32)` (`#RRGGBB` は alpha=0xFF として
  `0xFFRRGGBB` に packing)。
- **T7 (wasamo-runtime IR loader):** `parse_literal` は現状
  catch-all で reject。T7 で `RATIO` / `COLOR` terminal の正規 arm を
  追加し、Box `aspect` / `fill` 以外の位置で出現した場合は
  `WASAMO_ERR_IR_MALFORMED` で reject (defense-in-depth)。
- **emit ↔ render_lit の color packing helper 重複:** T5 で
  ラウンドトリップ test を書く際に共通化要否を再判断する。

これらはすべて progress file の T2–T13 として既に列挙済み。T1 単体で
新たに発見された follow-up は無い。
