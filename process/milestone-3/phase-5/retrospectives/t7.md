### 観測点 #6 (document-order paint) の許容判断

観測点 #6 (重なり描画順の owner-visible 観測) は T5 retro が「中段/footer
overlap で観測」と予測したが幾何的に誤りで (footer overflow は Grid 下方へ
clip され兄弟 Cell と重ならない)、T6 で owner-visible 観測点から除外し
[t5.md §Correction](./t5.md) に訂正済み。T7 evidence aggregation では
**追加の可視 fixture を作らず**、ADR/plan の "visible proof must observe
document-order paint" framing への **例外** として、以下を根拠に
**Phase 5 close に足るという許容判断を明示記録**する:

- **layout-side substrate (T2)**: `arrange_grid` は各 content child の
  `LayoutNode` に resolved offset/size を **document order** で毎パス
  書き込む (arrange cache 無し、architecture §6.8.7)。重なり時の前後関係は
  子の宣言順に一致する。
- **Visual-tree insertion-order 前提**: children は document order で Visual
  tree に挿入され、Composition の paint order = insertion order。
  document-order paint は layout / visual の構造上保証されており、追加の
  可視 fixture による直接観測がなくとも Grid の Phase 5 close を妨げない。

これは追加検証 task ではなく ADR/plan framing への例外の明示記録
(owner 確認 2026-05-30、Codex review 経由; T6 retro Follow-Up の引き継ぎ)。

## Main Learning

T7 の主要な学びは、**phase open 時に凍結された task list が、phase 途中の
owner 決定で所有が動いた項目について stale な ownership を持ちうる**こと。

T7-list は T0 時点で phase-`sync` close と `handoff.md` carry-forward を
**T7** 成果物として並べていた。しかし
[retrospectives.md §15 / §6.3](../../../procedures/retrospectives.md) は
最終的な `carry-forward` close と `handoff.md` 清書を **phase-end** retro
(項目 15) の責務と規定しており、さらに後発の
[T6 retro owner 決定 (2026-05-30)](./t6.md) が DPI carry-forward の
`handoff.md` 確定記載を phase-end とし「plan.md T7 へ owning bullet は
追記しない」と明言していた。T0 plan list はこの owner 決定より前に書かれた
ため stale だった。**最終 step の close では、T0 plan list を rubber-stamp
せず、phase 途中の owner 決定との整合を cross-check する** — そして
mutable phase plan は、この種の所有訂正を workaround せず revise するために
存在する (revise-don't-workaround)。
