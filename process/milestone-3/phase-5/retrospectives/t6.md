## Main Learning

T6 の主要な学びは、owner 指摘 3 件によって露見した **owner-visible 検証の
立て方** に集約される。

1. **assistant screenshot は per-monitor DPI 対応で撮る。** 初回キャプチャは
   `GetDpiForWindow`=96 を鵜呑みにし、DPI 非対応プロセスが仮想化 800×600
   矩形を取得 → しかし `CopyFromScreen` は物理 px を読むため、125% で
   1000×750 に bitmap 拡大された実ウィンドウの左上だけを撮り、右 (2* 列) と
   下を **取りこぼした**。これを owner が「高解像度ディスプレイなので 96dpi
   でない可能性、広めに撮れ」と指摘。修正: 撮影プロセスを
   `SetProcessDpiAwarenessContext` (PER_MONITOR_AWARE_V2) にし、物理
   window rect に crop。**比率・寸法を主張する前にキャプチャ系の座標空間を
   疑う。**

2. **比率のみ / 不可視 (clip) の現象に対する owner-visible 基準は、陽性対照を
   含めないと検証にならない。** owner 指摘 2 件:
   - **#1 star 可変性**: 起動時 1 サイズだけでは `C2:C1` の比率しか示せず、
     C1/C2 が **可変 track** である証明にならない (固定値が偶然同比率でも
     区別不能)。→ **リサイズ観測** (C0 固定・stars 伸縮) を必須化して初めて
     fixed + weighted-star の可変性を確認したと言える。
   - **#5 outer-bounds clip**: 「スパッと切られている」は **不可視内容**
     ゆえ検証不能 — 薄い帯は「もともと薄い cell」と区別できない。→ 基準を
     **「あるべき物が欠けている」** に変える (`gallery.ui` 宣言の
     `aspect: 4:1` + Text を期待値とし、画面上は ~36px 帯 + 文字消失) +
     **リサイズ陽性対照** (帯は薄いまま固定 / box 本来高さは伸びる)。
   - 一般原則: **現象が「比率」または「不在 (clip)」としてしか観測できない
     とき、owner-visible 基準には陽性対照 (リサイズ / source 参照) を入れ、
     「動作している」を「偶然同じに見える」から弁別できる形にする。**

3. **#6 は最小スライス設計上 #5 と排他で、本 slice では観測不可。** これは
   仕様上の排他ではなく、footer 1 個で overflow を下方 clip させる現設計の
   帰結。可視デモが要るなら gallery を汚さず専用 fixture を足すのが筋
   (Codex review 助言)。

4. **wasamo runtime は可変 DPI 非対応** (→ 項目 10)。
