## Main Learning

中心的な学びは **「Grid は flat-struct `LayoutNode` 拡張で収まり、
arrange-result cache は不要だった」** という R-D disposition の確定。
Phase 4 ScrollView の `applied_offset_y` / Phase 3 WrapPanel の
`wrap_measured_cross_bound` は measure→arrange を跨ぐ値を運ぶための
cache だったが、Grid のトラック解決は arrange 一箇所で決定的かつ安価
に再導出でき、per-Cell offset は各 child の `LayoutNode.offset` /
`.size` に直接書ける。R-D risk-table が "likely an arrange-result
cache" と見積もった分は実際には不要で、Phase 2–4 で増えた cache 系
フィールドの追加を Grid では避けられた。

副次的な学び:

- **DD-M3-P5-004 の `resolve_axis_tracks(tracks, AxisBound)` が
  そのまま pure free-function になり、ADR 擬似コードと 1:1 で
  unit-test できた。** mirror struct パターン (CLAUDE.md §Testing
  rules) を持ち出す必要は無く、トラック解決 / prefix 境界 / cell 矩形
  / alignment を全て free function に切り出して測れた。
- **unbounded-star error の発火点は measure ではなく arrange** が
  Phase 4 ScrollView と一貫する正解。measure 時の `avail = INFINITY`
  は Shrink 親が子に渡す標準 idiom なので、measure で発火させると
  有限セルに arrange される Grid まで誤って弾く。pure-logic テストは
  `resolve_axis_tracks(.., Unbounded)` を直接呼んで error 行を覆う
  (T4 runtime-fixture downgrade 条項)。
- **layout engine が `wasamo-ir` を一切 import していない既存様式**
  を再確認できた。`TrackSize` は `wasamo-ir` にも同名型があるが、
  pure engine 側は local mirror を定義し変換を build boundary (T3) に
  置く `Ratio` 先例に揃えた。IR crate への結合を避ける設計軸は Grid
  でも維持。
- **alignment の measure 入力は「サイズ制約」ではなく「軸ごとの
  stretchy 判定」で決める** (focused review #1)。固定サイズ child だけ
  だと measure が bound 非依存で乖離が見えないが、aspect Box / wrapping
  content では非 stretch 軸を cell extent で測ると spec の natural extent
  と食い違う。`cell_axis_is_stretchy(align, constraint)` を measure-bound
  選択と `align_in_cell` で共有し、stretch/`Fill` 軸 = cell extent、
  非 stretch 軸 = `INFINITY` (HStack/VStack の natural probe idiom) に
  統一した。`Fill`-as-stretch は既存 `cross_axis_position` 規約と一貫
  (Fill child は anchor すべき natural extent を持たない)。
