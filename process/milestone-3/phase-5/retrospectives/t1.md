## Main Learning

中心的な学びは **「構造的な IR フィールド追加 (`IrNode.kind_payload`)
は、`Default` 由来の暗黙補完を避けて全構築サイトで明示させ、コンパイル
エラーを露見の forcing function にするのが最も安全」** という R-C
disposition の確定。

- carrier c1 のフィールド追加は workspace 全体で 5 構築サイト
  (`wasamoc` lower 1、runtime loader prod 1 + round-trip test 3) に
  波及。IR 型に `Default` を derive せず (既存コードに
  `..Default::default()` は 1 箇所も無い style と一致)、新フィールドが
  各サイトで compile error として現れるようにした。spike risk-table が
  挙げた "`Default` derive / `IrNode::new` builder" 案は、この一貫性
  根拠で却下。

副次的な学び:

- R-A spike の **payload-less `Token::Star`** 選択が効いた。lexer に
  track-list 意味論 (融合 `n*` リテラル) を入れず、`n*` vs `n *` の
  区別を **parser 側の span 隣接** で再構成することで、DD-M3-P5-002 の
  "narrow Grid-specific parser path" 境界を字句レイヤに漏らさずに済んだ。
  既存 `RatioLit` の隣接判定 (`16:9` vs `16 :9`) と同じ機構。
- `Member::GridTracks` 列挙子の追加が ast / parser / check / lower の
  exhaustive match を同時に強制するため、これらは 1 commit に bundle
  せざるを得ない (CLAUDE.md commit rule の "intermediate states do
  not build" 例外)。emit も同 commit に畳んで、`wasamoc` 側 Grid
  pipeline (check→lower→emit) を 1 commit で coherent にした
  (低位化だけ landed して emit が track を黙って落とす中間状態を回避)。
- 検査の cross-cell 検証 (placement-vs-track-count、overlap) と
  per-cell 検証 (single-child、alignment 等) は、いずれも Grid context
  (track 数、cell 数) を要するため `check_grid` に一元化。`Cell` は
  `Grid` 外では無意味なので、`Cell` 診断を全て一箇所に置けた。generic
  walk 側の `Cell` arm は outside-Grid reject と content 再帰のみ。
