### 観測された事実（反証可能な signal）

T1 の AST seam 仮説どおり、`slot.*` は `PropertyBind` の name に収まった。
一方で、T4 開始前の plan は「Grid direct `slot.*`」だけに見えやすかったが、
T2/T3 の default slot path と組み合わせると、`Grid { Text {} }` も default
placement を持つ direct child として受理する必要があった。旧 reject test が
green から fail に反転したことが、その前提変更を明確に示した。

### 自己分析（どの層が外れたか）

外れたのは実装手順ではなく、accept-set の「direct child」という言葉の広さだった。
`slot.*` が付いた child だけを direct form と見ると、omitted placement default の
既存 runtime invariant と食い違う。T4 ではこの食い違いを checker の rectangle
collection に direct child を入れる形で解消した。

### 計画仮説・前提の問い直し（オーナーと）

T4 の task boundary は妥当だった。GUI proof や docs sync を混ぜずに compiler /
fixture surface だけで閉じたことで、branch/test-focused review の対象が明確に
なった。今後は author-surface task でも、accept-set の変更が既存 reject test を
どう反転させるかを start gate の planned proof obligations に明示するとよい。

### 反証可能な是正テスト

次の author-facing change では、旧 reject test 名を `rg` で拾い、accept-set 変更で
反転すべきもの / 残すべきものを start gate か初回 implementation pass で分類する。
今回でいえば `grid_non_cell_child_rejected` がその signal だった。

### 後続タスク / オーナーへ共有すること

T5 は `gallery.ui` の新 `slot.*` surface を前提に screenshot evidence を取る。
T7 は T4 で確定した Grid direct child default と ZStack bare reject を Moment 2
docs sync に反映する。Grid direct static child が受理されたことは、future Grid
structural mutation admittance とは別であり、直接 `if` / `for` of Grid cells は
引き続き T7 / phase-end carry-forward の対象。
