## 目標・前提・計画仮説の再点検

### 観測された事実（反証可能な signal）

- `log.md` には過去 task carry-over が無かった。T1 は Phase 7b 最初の
  implementation task として start gate を新規に作った。
- throwaway compiler probe は、最初に `IrNode::widget_children()` で止まり、
  helper が widget-only traversal の silent filter であることを示した。
  helper を一時更新すると、wasamoc lower/emit、runtime loader parser /
  validator / builder、runtime `zstack_placement` 系へ破断が広がった。
- source revert 後、production Rust diff は残らなかった。T1 commit の変更は
  process artifact のみ。
- self-review で、初期 plan の `WidgetNode.slot_data` field approach は
  spec 適合ではあるが durable child-slot model と型形状がずれることを検出。
- Claude review が、T1 artifact 内の propagation gap を検出した：
  preamble R-A stale、`docs/architecture.md` §6.7.9 T7 sync 漏れ、field
  rename 案との tradeoff 不足。
- post-commit verification は fmt / clean release build / clean debug build /
  workspace test が全 green。

### 自己分析（どの層が外れたか）

- **良かった点:** T1 を本番 migration ではなく recon として切り直し、throwaway
  edit を revert したうえで compiler surface を evidence にできた。plan を
  frozen prediction として扱わず、runtime/layout/IR の to-be code shape を
 再考できた。
- **外れた点:** 最初の artifact 修正では、方針変更を plan/log の carrier
  spelling に閉じ込めてしまい、preamble R-A と T7 spec-sync scope への伝播が
 遅れた。これは「設計判断を変えたら、その判断を読む入口すべてを同期する」
  という doc-side version of call-site audit の不足だった。
- **レビュー分業の効き方:** Claude review は、T1 の中核 recon は通しつつ、
  load-bearing spelling の伝播漏れを正しく指摘した。特に `docs/architecture.md`
  §6.7.9 は T1 では直接編集しないが、T7 owner として明記すべき scope だった。

### 計画仮説・前提の問い直し（オーナーと）

- **「T1 は no-production-code spike」** — 維持。throwaway source edit は
  compile-surface enumeration のみで、revert 後に source diff は残していない。
- **「plan の `WidgetNode.slot_data` approach で十分」** — 部分反証。
  low-cost / spec-compliant ではあるが、Phase 7b 完了時の code shape としては
  explicit `ChildSlot` record の方が durable model に合う。
- **「IR は struct variant でよい」** — 再考。runtime/layout を record にするなら
  IR も `IrChildSlot` wrapper にする方が、slot-local future fields と helper
  semantics を明確にできる。
- **「decisions directory を変更すべきか」** — 不要と判断。変更したのは
  implementer spelling / task plan であり、DD-fixed の child-slot-carried /
  `SlotData` / IR-B / reject+regenerate 方針は変えていない。

### 反証可能な是正テスト

- **doc-side carrier spelling audit:** `rg` で `IrMember::Widget { node, slot_data }`
  / `WidgetNode.slot_data` / `IrChildSlot` / `§6.7.9` を横断検索し、古い spelling が
  probe 履歴・比較対象・T7 sync target 以外に残っていないことを確認した。
- **process artifact scope check:** `git status --short` と committed diff で、
  T1 が process files のみを変更し、本番 source diff を残していないことを確認。
- **post-commit clean rebuild:** `cargo clean` 後に release build / debug build /
  workspace test を通し、T1 の doc/process-only commit が workspace を壊して
  いないことを確認。

### 後続タスク / オーナーへ共有すること

- **T2 へ:** `IrChildSlot` is the planned spelling. `widget_children()` は
