# T5 レトロスペクティブ

タスクブランチ: `feat/m3-phase-7b-t5`

T5 は ADR evidence item (4) の assistant 自動部分 — parent-interpreted
placement (`slot.*`) サーフェスの launch + DPI-aware screenshot +
assistant 解析 + positive control — を履行した。計画仮説では「shipped
gallery が既に placement の positive control を可視化している」前提
だったが、事前プローブでこれを反証。gallery の ZStack 子は全て
`slot.h-align: stretch` のみ、メイン Grid はキャプチャサイズで不可視、
継承スクリプトのクリック座標は stale で合成入力は Composition アプリ
のボタンを駆動しない、と判明した。よって意図的な placement-demo
サーフェス(owner 決定 A、default-open、Phase 8 除去マーカー)を
`gallery.ui` に追加し、ZStack `slot.h-align` の start/omitted→center/end
の3位置対比と、Grid の row/column/span + stretch-default vs centered
対比を1フレームで捕捉した。

コミット: `cd53356`(初回)+ `12c064f` / `74a3eee`(Codex レビュー対応
2 ラウンド)+ retro 2 件。**Phase-7b production Rust は変更なし**;

alignment_rejected`、既存挙動の pin)のみ追加。他は `gallery.ui` +

## 目標・前提・計画仮説の再点検

> 後続タスクの retrospective でも流用するダブルループ振り返り欄。
> 実行の巧拙（シングルループ）でなく、**設定した目標・前提・事前計画
> （= 検証すべき仮説）自体が妥当だったか**を、反証可能な signal とともに
> オーナーと問い直す。下の 5 サブセクションがひな型。

### 観測された事実（反証可能な signal）

- gallery の ZStack 子は **全て `slot.h-align: stretch`**(ソース
  grep）— `end` も alignment 対比も存在しない。
- キャプチャでメイン Grid は **不可視**(`t5-home.png` の home に Grid
  バンドが出ない)。
- 継承スクリプトの click 座標は現レイアウトで stale。
- 合成クリックが **サンドボックス内では不発**だった(当初これを app
  限界と誤判定)。**非サンドボックスでは駆動する**ことが後で判明。
- 固定トラック単一 cell Grid は描画、`aspect`-cell / star-column
  Grid は **arrange abort**(bisect で確定)。
- same-position の Phase 6 baseline 比較で photo 矩形が **20px Y ずれ**
  (Codex 計測)→ Phase 6 は別 gallery 版で baseline が誤りだった。
  T4-pre `3134287`(同一 content / bare 構文)と比較すると **pixel 一致**。

### 自己分析（どの層が外れたが）

- **前提層が外れた。** 「既存 gallery が placement の positive control
  を内包する」という plan.md の前提を、ソース確認せずに引き継いで
  いた。実際は「stretch のみ」「Grid 不可視」で、positive control の
  核心(alignment を変えると位置が変わる)が不在だった。
- **計画手段の前提も外れた。** 「proven capture script を再利用」は
  座標 stale で成立せず。さらに「合成入力が効かない」を **app 限界と
  即断**したのが二段目の誤り(実際はサンドボックス由来)。**制約の
  原因切り分け前に手段を諦めた** = シングルループ混入。
- baseline 選択でも **手段の誤り**:「bare は現 branch で再生成不可
  → 既存 Phase 6 evidence を baseline に」としたが、Phase 6 は別
  gallery 版で migration と無関係な差を持ち込んだ。正しくは T4-pre
  commit(同一 content)を baseline にすべきだった。
- 目標(item (4) assistant baseline + positive control + same-position)
  自体は妥当で、re-cut(意図的 demo サーフェス + 正しい baseline)で
  達成できた。

### 計画仮説・前提の問い直し（オーナーと）

- 「assistant にはできない」と結論する前に、**制約が環境由来か本質的か
  を切り分ける**(合成入力もサンドボックス由来だった)。GUI-evidence
  task は非サンドボックス/昇格デスクトップを前提に明記し、frame は
  committed code から再生成可能にする。
- same-position proof の **baseline は「同一 content・対象差分のみ」を
  満たすもの**(= 直前 commit)を選ぶ。見た目が近いだけの旧 evidence
  は無関係差を持ち込む。
- gallery を「検証サーフェス累積ホスト・Phase 8 で一括除去」と
  位置づける owner の前提は、A 選択の正当化に直結した。この
  位置づけを framing / handoff で明示しておくと後続が同じ判断を
  再現しやすい。

### 反証可能な是正テスト

- GUI-evidence task は **start gate で「frame は committed code から
  再生成できるか / 必要なら非サンドボックス実行か」を明示**する。
  是正できていれば、別環境でも同じ frame を再生成できる。
- same-position proof は **「対象の変更だけが差分の baseline」**(直前
  commit など)と比較し、pixel(bbox)で一致を示す。見た目近似の旧
  evidence を baseline にしない(反証 signal = 無関係な座標差)。
- Grid を positive-control サーフェスに使う場合、**固定トラック +
  非 ZStack-direct 配置 + aspect-free cell** を満たすかを authoring
  前にチェック。満たさなければ描画 abort で空フレームになる(反証
  signal = 空の scrim のみ)。

### 後続タスク / オーナーへ共有すること

- **T6**: owner-visible smoke は T6 所有(same-position の assistant
  portion は T5 で閉じた)。placement-demo は default-`false` なので、
  owner は home の「Open placement demo」で demo を、「Open lightbox」で
  lightbox を対話確認する。
- **T7 / phase-end**: placement-demo サーフェスの Phase 8 除去、および
  layout 発見(Grid-as-ZStack-child / aspect-in-cell)を candidate
  ledger に積む。owner triage で spec note 化 or 将来 fix を判断。
  合成入力は環境注記(`local-only`)で carry 対象外。
