## 目標・前提・計画仮説の再点検

> 後続タスクの retrospective でも流用するダブルループ振り返り欄。
> 実行の巧拙（シングルループ）でなく、**設定した目標・前提・事前計画
> （= 検証すべき仮説）自体が妥当だったか**を、反証可能な signal とともに
> オーナーと問い直す。下の 5 サブセクションがひな型。

### 観測された事実（反証可能な signal）

- gallery の ZStack 子は **全て `slot.h-align: stretch`**(ソース
  grep）— `end` も alignment 対比も存在しない。
- 800×650 キャプチャでメイン Grid は **不可視**(`t5-gallery-home-no-demo.png`)。
- 継承スクリプトの click(`Open lightbox`=400,382)は現レイアウトで
  外れ、プローブの open フレーム = closed フレーム。
- cursor 合成クリック / activate 後クリック / posted `WM_LBUTTON`
  の **3 手法すべてでボタン不発**(default-open へ切替で解決)。
- 固定トラック単一 cell Grid は描画、`aspect`-cell / star-column
  Grid は **arrange abort**(bisect で確定)。

### 自己分析（どの層が外れたが）

- **前提層が外れた。** 「既存 gallery が placement の positive control
  を内包する」という plan.md の前提を、ソース確認せずに引き継いで
  いた。実際は「stretch のみ」「Grid 不可視」で、positive control の
  核心(alignment を変えると位置が変わる)が不在だった。
- **計画手段の前提も外れた。** 「proven capture script を再利用」は
  座標 stale + 合成入力不発で成立せず。assistant GUI evidence の
  「対話遷移」依存そのものが脆い前提だった。
- 目標(item (4) assistant baseline + positive control)自体は妥当で、
  re-cut(意図的 demo サーフェス + default-open)で達成できた。

### 計画仮説・前提の問い直し（オーナーと）

- assistant GUI evidence のサブ画面は **無遷移で描画される形**
  (default-render / 起動時状態)に寄せるべき、を一般則として
  共有したい。対話遷移(click でモーダルを開く等)の検証は owner
  smoke(T6)か M4 の input-driver に委ねる。
- gallery を「検証サーフェス累積ホスト・Phase 8 で一括除去」と
  位置づける owner の前提は、A 選択の正当化に直結した。この
  位置づけを framing / handoff で明示しておくと後続が同じ判断を
  再現しやすい。

### 反証可能な是正テスト

- 今後の GUI-evidence task は **start gate で「証拠サーフェスは
  起動時に無遷移で描画されるか」を明示確認**する(対話遷移が要る
  なら owner smoke へ委譲と明記)。是正できていれば、合成入力不発の
  環境でも assistant baseline が再現可能(= フレームが committed
  code から再生成できる)。
- Grid を positive-control サーフェスに使う場合、**固定トラック +
  非 ZStack-direct 配置 + aspect-free cell** を満たすかを authoring
  前にチェック。満たさなければ描画 abort で空フレームになる(反証
  signal = 空の scrim のみ)。

### 後続タスク / オーナーへ共有すること

- **T6**: same-position lightbox proof と owner-visible smoke は T6
  所有。placement-demo は default-open なので、owner は「Close demo」
  で home へ、lightbox を対話で開いて Phase 6/7 evidence と同位置
  比較。
- **T7 / phase-end**: placement-demo サーフェスの Phase 8 除去、
  および 3 件の layout/input 発見(Grid-as-ZStack-child / aspect-in-cell
  / 合成入力不発)を candidate ledger に積む。owner triage で spec
