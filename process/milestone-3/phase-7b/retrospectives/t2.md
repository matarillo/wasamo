# T2 レトロスペクティブ

タスクブランチ: `feat/m3-phase-7b-t2`

T2 は Phase 7b implementation の **IR / textual-IR migration**。T1 から
持ち越された `IrChildSlot` / `IrSlotData` carrier を実装し、既存 author
surface（Grid `Cell`、ZStack bare `h-align` / `v-align`）を IR slot data
へ lower する。Emitter は canonical `child { placement ... node ... }`
textual IR を出し、runtime loader は canonical child-slot record を parse
しつつ、旧 placement textual IR を named diagnostic で reject する。

Runtime / layout の structural migration は T2 の責務ではない。T2 は
Seam A として、parsed `IrSlotData` を既存の
`WidgetData::Grid.cell_placements` / ZStack placement path へ bridge した。
この adapter と parallel storage の削除は T3 owner として
[../implementation/log.md](../implementation/log.md) に明示済み。

T2 commit:

- `e07a12e feat(m3-phase-7b): land T2 IR child slots`

## チェックリスト（task-end、項目 1〜11）

1. **今回の主な学び。** 三つ。
   - **(a) IR schema migration は helper semantics の migration でもある。**
     `IrMember::Widget(IrChildSlot)` へ変えるだけでは足りず、
     `widget_children()` は placement-insensitive helper として `slot.node`
     だけを返し、placement-sensitive sites には `widget_child_slots()` を
     使わせる必要があった。T2 の trap-#1 table はこの分類が主成果。

## 目標・前提・計画仮説の再点検

### 観測された事実（反証可能な signal）

- T1 carry-over correctly predicted the major fracture surface:
  `wasamo-ir`, `wasamoc` lower/emit, runtime loader parse/validate/build,
  and a few integration tests all had to move from `IrNode` to `IrChildSlot`.
- The workspace build forced most tuple-shape call sites to update, but it
  did not by itself prove reject branch coverage. Additional runtime loader
  tests were needed for missing / duplicate child-slot blocks, unknown
  placement kind/key, wrong parent placement kind, and stale bare ZStack
  placement props.
- Canonical textual IR could be introduced without breaking existing `.ui`
  authoring: old Grid `Cell` and old ZStack direct-child placement props still
  lower successfully, but no longer survive into emitted textual IR.
- Runtime behavior remained green through integration tests only because T2
  bridged `IrSlotData` back to legacy placement storage. This is a positive
  compatibility result, not a structural close.
- The minimal end gate was useful: the branch/test map exposed parse branches
  that would otherwise have hidden under broad `cargo test --workspace` green.

### 自己分析（どの層が外れたか）

- **良かった点:** T2 started by treating `plan.md` as a hypothesis and
  tightened responsibility before implementation. That avoided mixing T2 IR
  migration with T3 runtime/layout storage deletion.
- **良かった点:** After the first green run, the end-gate discipline caused a
  second pass over reject branches. That pass added direct tests for newly
  written parser / validator branches and removed stale `Cell.*` wording from
  canonical Grid diagnostics.
- **外れた点:** Initial implementation confidence came slightly too early from
  workspace green. The stricter branch/test map showed that "green" is not the
  same as "every new diagnostic branch has a direct trigger." The correction
  happened before close, but it is a useful warning for T4 where the reject
  matrix will be wider.
- **残る注意:** T2 left parser compatibility for placement-free direct `node`.
  That is intentional, but it needs careful wording in T7 so the project does
  not accidentally promise a fully strict textual parser before such a change
  is explicitly decided.

### 計画仮説・前提の問い直し（オーナーと）

- **「T2 owns IR/textual-IR, not runtime structural storage」** — 維持。
  T2 delivered the IR/textual boundary and left T3 with explicit adapter
  removal ownership.
- **「Existing author surfaces keep working until T4」** — 維持。T2 lower still
  accepts Grid `Cell` and ZStack bare placement authoring, while emitted IR is
  canonicalized.
- **「Loader stale old-form placement IR must reject」** — 達成。ただし
  "stale placement form" と "placement-free legacy direct child" は別物として
  扱う必要がある。
- **「cargo test green is enough evidence」** — 反証。T2 end gate required a
  machine-derived branch/test map; that surfaced extra tests that broad green
  alone would not justify.

### 反証可能な是正テスト

- **New reject branches need branch-first evidence before close.** T4 should
  prepare the reject matrix as rows whose names match actual parser/checker
  branches, then prove each row with a direct test name and a source query
  (`rg` / `git diff` / `git grep`). A broad "matrix tested" or workspace green
  should fail the close gate unless each sub-branch has a needle and owner.

### 後続タスク / オーナーへ共有すること

- T3 should begin from the T2 Seam A rows in
  [../implementation/log.md](../implementation/log.md), not from a fresh search:
  `grid_placement_from_slot`, `zstack_placement_from_slot`,
  `WidgetData::Grid.cell_placements`, layout `cell_placements`, and
  `WidgetNode.zstack_placement` are the known removal surface.
- T4 should reuse T2's branch/test-map style for the `slot.*` checker matrix.
  The high-risk pattern is one test name covering multiple semantic branches;
  subcase needles should be explicit.
- T7 should avoid describing parser compatibility too loosely. The landed
  contract is canonical emit + canonical parse + stale placement reject, with
  transitional lenience for placement-free direct child nodes.
