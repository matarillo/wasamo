# T2 レトロスペクティブ

タスクブランチ: `feat/m3-phase-7b-t2`

T2 は Phase 7b 実装の **IR / テキスト IR 移行**。T1 から
持ち越された `IrChildSlot` / `IrSlotData` carrier を実装し、既存の作者向け記法
（Grid `Cell`、ZStack の裸 `h-align` / `v-align`）を IR の slot data
へ lower した。Emitter は正規形 `child { placement ... node ... }`
テキスト IR を出し、実行時 loader は正規 child-slot record を parse
しつつ、旧 placement テキスト IR を名前付き診断で reject する。

Runtime / layout の構造移行は T2 の責務ではない。T2 は
Seam A として、parse した `IrSlotData` を既存の
`WidgetData::Grid.cell_placements` / ZStack placement path へ bridge した。
このアダプタと並列ストレージの削除は T3 担当として
[../implementation/log.md](../implementation/log.md) に明示済み。

T2 commit:

- `e07a12e feat(m3-phase-7b): land T2 IR child slots`
- `03912af process(m3-phase-7b): record T2 task retrospective`

Claude review で指摘された不足のうち、merge 前に閉じるべき A / B / D は
T2 レビュー追補として修正対象にした。具体的には Grid 座標負値の
parse reject、Grid slot payload の emit-style render -> parse 陽性対照、
T2 checklist `[x]` 更新である。任意指摘 C / F についても、安価に
閉じられるパーサ防御分岐テストと ZStack stale diagnostic の意図コメントを
追加した。

## 目標・前提・計画仮説の再点検

### 観測された事実（反証可能な signal）

- T1 carry-over は主要な破断面を正しく予測していた。`wasamo-ir`、
  `wasamoc` lower/emit、runtime loader parse/validate/build、少数の
  integration test が `IrNode` 直持ちから `IrChildSlot` へ移行する必要があった。
- Workspace build は tuple-shape call site の大半を compile error として
  強制的に露出させたが、それだけでは reject branch coverage の証明には
  ならなかった。Missing / duplicate child-slot block、unknown placement
  kind/key、wrong parent placement kind、stale bare ZStack placement props には
  runtime loader の直接テストが必要だった。
- Claude review 後、Grid 座標負値の parse reject と Grid slot payload の
  陽性対照が不足していることが確認された。これは T2 自身の close
  responsibility なので、後続 task へ流さず T2 レビュー追補として閉じた。
- 正規テキスト IR は既存 `.ui` authoring を壊さず導入できた。旧 Grid
  `Cell` と旧 ZStack direct-child placement props は引き続き lower できるが、
  emitted textual IR には残らない。
- Runtime behavior が integration test でグリーンだったのは、T2 が
  `IrSlotData` を legacy placement storage へ bridge したためである。これは
  compatibility の positive result であり、structural close ではない。
- Minimal end gate は有効だった。Branch/test map によって、単なる
  `cargo test --workspace` グリーンでは隠れる parse branch が露出した。

### 自己分析（どの層が外れたか）

- **良かった点:** T2 は `plan.md` を仮説として扱い、実装前に責務境界を
  締め直した。これにより、T2 の IR 移行と T3 の runtime/layout storage
  deletion を混ぜずに済んだ。
- **良かった点:** 最初のグリーン後、end-gate discipline によって reject branch を
  もう一度見直した。その結果、新しく書いた parser / validator branch の直接
  テストを追加し、正規 Grid diagnostic から stale `Cell.*` wording を除去した。
- **外れた点:** それでも Grid parse 方向の陽性対照と
  `expect_nonnegative_u32` の負値 branch は、Claude review まで不足に気づけなかった。
  workspace グリーンと広い branch map は十分条件ではなく、payload value の正写像を
  見る陽性対照が別途必要だった。
- **残る注意:** T2 は placement-free direct `node` の parser compatibility を残した。
  これは意図的だが、T7 では完全に strict な textual parser を約束したかのように
  書かないよう注意が必要である。

### 計画仮説・前提の問い直し（オーナーと）

- **「T2 は IR/textual IR を所有し、runtime structural storage は所有しない」** — 維持。
  T2 は IR/textual boundary を届け、adapter removal は T3 担当として残した。
- **「既存 author surface は T4 まで動かし続ける」** — 維持。T2 lower は
  Grid `Cell` と ZStack bare placement authoring を引き続き受け付ける一方で、
  emitted IR は正規化する。
- **「Loader は stale old-form placement IR を reject する」** — 達成。ただし
  "stale placement form" と "placement-free legacy direct child" は別物として
  扱う必要がある。
- **「`cargo test` グリーンだけで十分な証拠になる」** — 反証。T2 end gate は
  機械出力に基づく branch/test map を要求し、その後の independent review は
  Grid payload 陽性対照の不足も露出させた。広いグリーンは必要だが、
  branch / payload ごとの直接証明の代替にはならない。

### 反証可能な是正テスト

- **新しい reject branch は close 前に branch-first evidence を持つ。** T4 では
  reject matrix を actual parser/checker branch に対応する row として作り、各 row を
  direct test name と source query（`rg` / `git diff` / `git grep`）で証明する。
  広い「matrix tested」や workspace グリーンは、sub-branch ごとの needle と owner が
  ない限り close gate を通さない。
- **陽性対照は payload value を読む。** Grid のように parse 成功や child
  count だけでは row / column / span / alignment の取り違えを検出できない場合、
  emit-style render -> parse equality か、parse 後の `IrSlotData` field assert を
  close proof に含める。

### 後続タスク / オーナーへ共有すること

- T3 は [../implementation/log.md](../implementation/log.md) の T2 Seam A rows から
  始める。`grid_placement_from_slot`、`zstack_placement_from_slot`、
  `WidgetData::Grid.cell_placements`、layout `cell_placements`、
  `WidgetNode.zstack_placement` が既知の removal surface である。
- T4 は `slot.*` checker matrix に T2 の branch/test-map style を再利用する。
  危険な pattern は、複数の semantic branch を一つの test name に隠すこと。
  Subcase needle は明示する。
- T7 は parser compatibility を広く書きすぎない。実際に landed した契約は
  正規 emit + 正規 parse + stale placement reject であり、
  placement-free direct child node への transitional lenience は別扱いである。
