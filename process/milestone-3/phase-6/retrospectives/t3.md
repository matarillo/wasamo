10. New cross-task / cross-phase design constraints: one `carry-forward`
    candidate plus two `local-only` closures (no future constraint, so
    not forwarded).
    - **Constraint (`carry-forward`)**: the runtime loader now has a
      global parent-context placement-prop validation pass for `h-align`
      / `v-align`; any later `IrMember` migration, control-flow body
      walk, or widget that wants to consume those names must update this
      gate together with the Grid/ZStack alignment extraction defaults.
      - **Evidence**: `validate_phase6_zstack_node_invariants` recurses
        the loaded widget tree and admits placement props only for a
        ZStack direct child or Grid `Cell`; `extract_alignment_prop_or`
        makes the Grid default `Stretch` and ZStack default `Center`
        explicit at the call sites.
      - **Placement**: `carry-forward` candidate for phase-end review.
        It is already compatible with the current T4 migration plan
        because T4's schema-change spike owns loader/validator walker
        migration.
    - **Single-child / nested `ZStack` test gap (`local-only`)**: not a
      future constraint. `measure_zstack` / `arrange_zstack` branch on
      neither child count nor child kind — both recurse through the
      generic `measure` / `arrange` path — so single-child and nested
      `ZStack` exercise no code path the multi-child fixtures and the T2
      pure-logic tests do not already cover. Re-trigger criterion: add a
      dedicated test only when `ZStack` gains an arity-keyed branch or a
      branch that special-cases a `ZStack`-typed child; the task that
      introduces that branch owns the test.
    - **`Visual.Clip()` presence-only assertion (`local-only`)**: not a
      Phase-6-introduced constraint. The `Clip().is_ok()` /
      `is_err()` presence/absence check is the existing codebase-wide
      fixture convention shared with Grid / ScrollView / WrapPanel, and
      the ZStack clip is zero-inset by construction (`CreateInsetClip()`
      with no inset set). Raising the bar to pin inset *values* would be
      a cross-cutting test-convention change owned by
      [CLAUDE.md §Testing rules](../../../../CLAUDE.md#testing-rules) /
      `docs/notes/verification-environments.md` and applied uniformly to
      all four widgets — not a Phase 6 carry-forward.
11. Follow-on task-list review: no revision needed. T4 already owns the
    loader / validator walker migration for the `IrMember` schema change;
    T7/T8 still own the real-pixel paint-precedence observation on the
    lightbox, and T5/T6 still own conditional reactivity and static title
    wiring.
