## Checklist (task-end, items 1–11)

1. **Main learning.** R1 was a narrow host-wiring bug, not a new Window
   property model. Reading the already-lowered `component.root.props`
   static `title` at the `wasamo_load_ui` seam let the runtime set the
   initial native title without adding ABI surface, while preserving the
   DD-M3-P6-006 dynamic-title deferral (`bind title = ...` remains a future
   window-property binding seam). The useful split is "missing/empty is a
   benign default; wrong-typed direct IR is malformed", which keeps the
   fallback from becoming a blanket tolerance. Review follow-up tightened the
   implementation so that malformed-title rejection is single-sourced in
   validation; title resolution is now only an infallible projection over a
   validated component.
2. **Specification document changes:** none. No `abi_spec.md`,
   `architecture.md`, or `dsl_spec.md` edit was needed; T6 implements the
   already-accepted DD-M3-P6-006 static path. Non-normative counter example
   README files were updated because their "DSL title is dropped" note became
   stale.
3. **Post-change verification:** green (recorded in
   [log.md](../implementation/log.md)).
   - `cargo fmt --all -- --check` — green.
   - `cargo clean` — completed (`4329 files, 1.4GiB` removed).
   - `cargo build --release --workspace` — green.
   - `cargo build --workspace` — green.
   - `cargo test --workspace` — green, including
     `window_title_integration`.
   - Scoped checks: `cargo test -p wasamo-runtime --lib static_window_title`,
     `cargo test -p wasamo-runtime --test abi_load_ui`, and
     `cargo test -p wasamo-runtime --test window_title_integration` — green.
   - Existing Cargo warnings about the `wasamo` linkable target /
     `wasamo-sys` import-library ordering were observed.
4. **Design judgments / trade-offs to consult PO:** none. The dynamic
   title implementation remains deliberately deferred per DD-M3-P6-006; T6
   did not introduce a new trade-off or host-facing surface.
5. **Out-of-task refactors or structural changes:** none in code. The only
   adjacent doc change was the three counter example READMEs. This was not a
   pure stale-text removal: the prior "DSL title is dropped" caveat (accurate
   pre-T6) was flipped to a new positive observable ("titled `"Counter"`"),
   because the T6 runtime change applies to every host, not just the gallery.
   To keep that claim substantiated rather than inferred, all three hosts
   were built and launched and their live window title read back —
   counter-rust (`cargo build`), counter-c (CMake / MSVC, Release), and
   counter-zig (`zig build` 0.16.0) each reported `"Counter"` (not the
   `"Wasamo"` default) with a live HWND (recorded in
   [log.md](../implementation/log.md)). No dedicated positive control was
   needed: `"Counter"` directly falsifies the only realistic
   wrong-implementation output (`"Wasamo"`), and the mechanism's
   input-varied discrimination is already pinned by the Gallery integration
   fixture.
6. **Need for an additional DD:** none.
7. **Existing-ADR Proposed item / Proposed → Accepted promotion:** none.
8. **Milestone-plan AC / phase-shape additions or changes:** none. T6
   discharges R1's Windows-runtime evidence line; T7/T8 still corroborate
   the title in gallery assistant/owner smoke frames.
9. **Carry-over temporary implementation / approximations / new
   `dead_code`:** none. Dynamic title is an accepted DD deferral, not a T6
   temporary implementation. Review follow-up removed the redundant
   fallible resolve branch, so malformed-title rejection has no logically
   unreachable ABI mapping arm.
10. **New cross-task / cross-phase design constraints:** **yes —
    carry-forward to the later Window-prop seam.**
    - **Constraint:** Window-derived component props that are wired after T6
      should follow the same validate-then-resolve split: absent / empty may
      choose a benign default where the DD says so, but wrong-typed direct IR
      must be a loader malformed error rather than a silent fallback.
    - **Evidence:** T6 changes `title` from silently dropped metadata to a
      loader-validated Window prop consumed by `wasamo_load_ui`; the
      malformed branch is pinned by `static_window_title_rejects_non_string_root_prop`
      and the ABI status assertion in `abi_load_ui`.
    - **Placement:** `carry-forward` candidate for the M4 / Q2
      `title` / `backdrop` / `theme` Window-prop wiring. The dynamic-title
      writer seam itself was already recorded in DD-M3-P6-006; this item is
      the loader-validation half.
11. **Downstream-task revision:** not needed. T7 and T8 already require the
    gallery title bar to read `"Gallery"`; T6's new
    `window_title_integration` fixture gives the CI-gated R1 evidence before
    that visible-smoke corroboration.

## Implementation-Gate Closure

- **#2 missed side effects:** static root `title` now affects native window
  creation through `wasamo_load_ui` → `window::create`; dynamic
  `bind title`, `backdrop`, and `theme` remain unwired as planned.
- **#4 branch tests:** `static_window_title_resolves_string_or_default`
  covers absent / empty / string resolution;
  `static_window_title_rejects_non_string_root_prop` covers the sole
  non-`Str` loader rejection; `abi_load_ui` covers the
  `WASAMO_ERR_IR_MALFORMED` mapping from that validation gate.
- **#5 carry-forward:** later Window-derived props should reuse the T6
  validate-then-resolve split rather than silently accepting wrong-typed
  direct IR.
- **#7 Windows-runtime state evidence:** `static_component_title_reaches_native_window`
  lowers a `.ui` declaring `title: "Gallery"`, calls `wasamo_load_ui`, and
  reads the live HWND title with `GetWindowTextW`. Positive control:
  `"Gallery"` is observed instead of the previous `"Wasamo"` default. T7/T8
  remain the screenshot / human-visible corroboration for the title bar.
