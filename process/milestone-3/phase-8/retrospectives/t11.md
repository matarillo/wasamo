> オーナーと問い直す。下の 5 サブセクションがひな型。

### 観測された事実（反証可能な signal）

- plan の「§4.17 / §4.18 markers flip」bullet は source と矛盾した:
  `grep "Phase status" docs/dsl_spec.md` で Phase 8 の marker は §4.17 の
  1 箇所のみ。T0 時点の bullet が Moment 1 で実際に landed した文書構造を
  反映していなかったことの反証可能な検出。
- 「divergence corrections folded」bullet も T8(1.13)/ T9(1.14)の
  revision history が既に消化済みであることを示していた。
- 実 diff は T9 allowed surface の 7 行と 1:1 で突き合わせられ、超過も
  欠落もなかった(end gate conformance check)。
- 全 local gates が first-run green、path-scoped git range は空のまま。

### 自己分析（どの層が外れたか）

- **計画仮説の粒度が Moment 1 時点で凍っていた:** T11 bullet は
  「T8-T10 が何をどこまで消化するか」を予測で書いており、実績との差分
  (marker の実在、fold の消化)が残っていた。実行の問題ではなく、
  最終 sync タスクの plan は中間タスクの実績で陳腐化するという構造的な
  性質。着手時の批判的再点検(本タスクで実施)がその補正装置として
  機能した。
- **T9 の事前列挙が当たった:** 「T11 で本文を直したくなったら別 review
  concern」という制約は、実際に §4.18 marker 問題を「flip 対象を狭める」
  方向で解決させ、本文に手を入れる誘惑を断った。
- **外れは軽微で、方向は保守側:** 訂正はいずれも「やることを減らす」
  訂正であり、scope 拡大側の外れはなかった。

### 計画仮説・前提の問い直し（オーナーと）

- **「T11 は divergence を探しに行くべきか」** — 行かない。
  T8 の readiness audit と T9 の G(4) remediation が消化済み。T11 で
  新たに見つかる本文問題は、T11 diff に混ぜず別 review concern として
  owner-visible にする(今回その分岐は使われなかった)。
- **「promotion 記録は revision-history 行だけで足りるか」** — 足りない。
  anchor(public-draft change history)は「公開 record + M3 決定への
  リンク」という読者向けの役割、revision table は編集履歴という役割で、
  別物。top Status の従来文言もこの区別を前提にしていた。
- **「candidate ledger は handoff.md に直接書くべきか」** — 書かない。
  retrospectives.md の 3 段階前送り(候補記録 → item 15 確定 → §6.3
  清書)どおり、T11 は log.md に候補を列挙するまで。`implementation/
  handoff.md` の確定成果物化は phase-end batch の所有。

### 反証可能な是正テスト

- 最終 doc-sync タスクの start gate では、plan の各 bullet を「既に
  どのタスクが消化したか / 対象が source に実在するか」で分類してから
  diff を切る(分類表が空欄の bullet を残したまま実行に入らない)。
- 事前列挙された allowed surface がある場合、end gate は「列挙 vs 実
  diff」の conformance check を必須 artifact にする(今回の形式を維持)。
