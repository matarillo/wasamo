## 目標・前提・計画仮説の再点検

> 後続タスクの retrospective でも流用するダブルループ振り返り欄。
> 実行の巧拙（シングルループ）でなく、**設定した目標・前提・事前計画
> （= 検証すべき仮説）自体が妥当だったか**を、反証可能な signal とともに
> オーナーと問い直す。下の 5 サブセクションがひな型。

### 観測された事実（反証可能な signal）

- `ToggleButton` runtime 実装は `ir_loader.rs` と `widget.rs` に集中し、layout
  algorithm 変更は不要だった。
- `ButtonData` に `checked` を足して `WidgetData::ToggleButton` を別 variant に
  する形で、Button visual / click / hover / layout leaf を共有できた。
- focused tests と full workspace tests は green。mock-free Windows integration
  fixtures で default false、literal true、binding state flip、alpha exclusion、
  disabled click suppression を確認できた。
- 最初の compile failure は helper 抽出による borrow overlap、次の failure は
  test type 名の取り違えで、どちらも root cause を特定してから rerun green にした。

### 自己分析（どの層が外れたか）

- **良かった点:** T4 start gate で Gallery / screenshot / host parity を明示的に
  範囲外へ戻したため、runtime task が T5/T7 の責務を飲み込まずに済んだ。
- **外れた点:** Button-family helper は「共通化すればよい」だけではなく、
  Rust の field borrow 形まで変える。既存 direct match が暗黙に持っていた
  disjoint-field borrow の性質を、helper 化で一度失った。
- **計画仮説の外れ:** `style` を Button-family property として mirror することと、
  `style` を bindable にすることは別だった。runtime catalog では static style は
  受けるが style binding は reject するように切り分けた。

### 計画仮説・前提の問い直し（オーナーと）

- **「T4 は runtime half」** — 維持。loader / widget / visual / Windows runtime
  fixtures までで閉じ、Gallery integration は T5。
- **「ToggleButton は Button-family sharing」** — 維持。ただし runtime kind は
  `WidgetData::ToggleButton` として分け、`checked` support boundary を保った。
- **「R-2 を T4 で完全に閉じるか」** — 部分的に閉じる。runtime brush 差分は
  T4 で証明し、final Gallery background 上の読み分けは T5/T7 へ carry-forward。
- **「runtime loader の unknown attr policy を一般化するか」** — しない。T4 は
  `ToggleButton` の closed catalog だけを mirror し、古い Button-wide policy は
  別判断として残した。

### 反証可能な是正テスト

- 新しい Button-family kind を足す場合、`WidgetData` variant、constructor、
  property get/set、hit-test、hover、layout leaf、loader validation、
  `resolve_prop_key` を `rg` audit で列挙する。
- visual-state task では「runtime brush/state fixture」と「final GUI screenshot」を
  同じ証拠として扱わず、どちらの task がどちらを所有するかを start gate で分ける。
- helper 抽出時は、既存 direct match が field-level borrow に依存していないかを
  focused compile で早めに確認する。

### 後続タスク / オーナーへ共有すること

- **T5 へ:** `ToggleButton` runtime は available。Gallery tab-band は
  `checked:` binding + `clicked` block assignment で live exclusion できる。
  T5 が background / tab styling を変えたら R-2 を再確認する。
- **T7 へ:** T4 の evidence は live brush / state の runtime proof。T7 は final
  Gallery screenshots で selected/exclusion two-frame positive control を別途撮る。
- **phase-end へ:** runtime defensive-reader catalog mirror を future widget-kind
  rule として handoff するか、T4-local learning に閉じるか item 15 で再判定する。
