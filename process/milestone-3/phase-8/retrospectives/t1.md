## 目標・前提・計画仮説の再点検

> 後続タスクの retrospective でも流用するダブルループ振り返り欄。
> 実行の巧拙（シングルループ）でなく、**設定した目標・前提・事前計画
> （= 検証すべき仮説）自体が妥当だったか**を、反証可能な signal とともに
> オーナーと問い直す。下の 5 サブセクションがひな型。

### 観測された事実（反証可能な signal）

- `wasamo-ir/src/lib.rs` の `IrNode.widget_type` は `String` で、T1 の
  wrong-kind probe は `wasamoc check` warning + exit 0 だった。
- `wasamoc/src/check.rs` には `unknown_widget_type_is_warning_not_error`
  という既存テストがあり、warning-only は偶然ではなく現在の期待動作だった。
- Phase 8 には既存の retained capture script が無かった。過去 phase の
  capture scripts は存在するが、Phase 8 統合 surface の座標 ground truth では
  ない。
- T1 commit 後の workspace は clean で、fmt / clean build / test は green。

### 自己分析（どの層が外れたか）

- **良かった点:** T1 を production implementation ではなく recon として扱い、
  source facts に基づいて T3/T4/T5/T6 の owner と risk を具体化できた。
- **外れた点:** 初回 retrospective はテンプレートの形式に寄せ切れておらず、
  item 10 の制約検出器としての構造と、5 サブセクションの double-loop 欄を
  落としていた。
- **計画仮説の外れ:** 「widget-kind addition は compiler error で網羅できる」
  という仮説と、「retained capture scripts の座標再導出が主作業になる」
  という仮説が、どちらも source recon で反証された。

### 計画仮説・前提の問い直し（オーナーと）

- **「T1 は no-production-code spike」** — 維持。probe は一時ファイルに閉じ、
  production source diff は残していない。
- **「T3/T4 は compile-error-forcing なら bundle」** — 反証済み。string-carried
  のため default split を採用し、T3 は compiler/IR、T4 は runtime/visual を
  それぞれ所有する。
- **「unknown widget warning-only policy は T1 で変更するか」** — 変更しない。
  ただし、これは `ToggleButton` 実装の範囲を超える診断方針なので、将来 hard
  diagnostic 化するなら owner / decision 判断として扱う。
- **「capture evidence は既存 script 座標の再導出で足りるか」** — 足りない。
  T5/T7 は統合後の Phase 8 surface から新しい座標と positive controls を導く。

### 反証可能な是正テスト

- 新しい widget kind を追加する task は、未知 kind probe が warning + exit 0 に
  なる限り、known-widget positive fixture を持つ。T3 では
  `ToggleButton` が no-warning で admitted されることをテストで示す。
- plan の条件文は、T1 が反証したら条件文のまま残さず、resolved statement に
  更新する。今回の T3/T4 split 文がその是正例。
- evidence script については、「retained」と書く前に phase-local script の有無を
  列挙する。無い場合は、過去座標再利用ではなく新規 derivation と記録する。

### 後続タスク / オーナーへ共有すること

- **T3 へ:** `ToggleButton` admission は check success だけでは証明にならない。
  known-widget / no-warning positive fixture と SI-3 reject tests を close artifact
  に含める。
- **T4 へ:** runtime loader は unknown widget を reject する経路を持つが、T1 は
  loader 実行 probe まではしていない。T4 の loader re-reject tests で runtime 側の
  boundary を閉じる。
- **T5/T7 へ:** Phase 8 capture coordinates は統合 surface から新規に導く。過去
  evidence scripts は reference であり、retained ground truth ではない。
- **オーナーへ:** unknown widget を warning-only のままにするか hard diagnostic に
  変えるかは、今後必要になった時点で別判断にする。T1 は変更しない判断を明示し、
  T3 で黙って変えないことを申し送る。
