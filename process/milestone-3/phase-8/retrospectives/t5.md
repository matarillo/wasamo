## 目標・前提・計画仮説の再点検

> 後続タスクの retrospective でも流用するダブルループ振り返り欄。
> 実行の巧拙（シングルループ）でなく、**設定した目標・前提・事前計画
> （= 検証すべき仮説）自体が妥当だったか**を、反証可能な signal とともに
> オーナーと問い直す。下の 5 サブセクションがひな型。

### 観測された事実（反証可能な signal）

- `ToggleButton` alpha exclusion works in the real Gallery surface:
  `default-all`, `selected-albums`, and `selected-favorites` show exactly one
  selected background, and the selected background moves after clicks.
- `capture-t5-gallery.ps1` initially failed inside the sandbox with the same
  off-screen `CopyFromScreen` symptom as T2, then succeeded outside the
  sandbox with the window at `(0,0)`.
- T2 and T5 both reached accepted screenshot evidence only through the
  visible-desktop path. T5 also needed absolute coordinates for tab,
  lightbox, close, and scroll actions; the committed script records those
  coordinates explicitly.
- The final `.ui` still contains no placement demo, footer clip demo,
  static ten-photo strip, mutation dashboard, or verification menu.

### 自己分析（どの層が外れたか）

- **良かった点:** T5 start gate で "Rust surface owner" と切ったため、T7 の
  authoritative evidence を飲み込まずに済んだ。
- **外れた点:** T5 start gate は "derive coordinates from the final surface"
  までは疑ったが、T2 と T5 の再発を受けてなお「座標ベース screenshot
  capture を T7 の authoritative evidence 様式として採用し続けること自体」を
  十分に問い直していなかった。
- **計画仮説の外れ:** "coordinates can be re-derived per task" という前提は
  T5 precheck には十分だったが、T7 の merge-gate evidence には弱い。
  authoritative capture は、sandbox 外の visible desktop を前提条件として扱い、
  harness fragility を evidence risk として計画に明示する必要がある。

### 計画仮説・前提の問い直し（オーナーと）

- **「T5 は final GUI evidence まで持つか」** — 持たない。T5 は first-render
  direction check と precheck evidence までで、T7 が authoritative evidence を
  所有する分割を維持する。
- **「T7 も同じ coordinate screenshot harness をそのまま使えば足りるか」** —
  そのままでは足りない。T7 は visible-desktop / outside-sandbox を実行前提にし、
  coordinate automation を fragile dependency として扱う。代替の semantic
  hit-testing / query hook は M3 には無いため、方式自体は継続するが、前提条件と
  failure mode を T7 start gate で明示する。
- **「beta fallback が必要か」** — 不要。live alpha exclusion は T5 Rust Gallery
  surface で動作した。
- **「mutation controls を Gallery に戻すか」** — 戻さない。T2 の owner
  disposition と Phase 7 evidence citation に基づき、T8 audit に持ち越す。

### 反証可能な是正テスト

- T7 start gate は、authoritative GUI evidence の前提として
  "visible desktop / outside sandbox required" と "coordinate harness is a
  known fragile dependency" を選択・記録してから capture approach を決める。
- GUI capture script が複数 state をまたぐ場合、state-changing click の直後に
  "その state になった" frame を保存する。この実行上の補強は #6/#7 側の
  artifact として扱い、double-loop 欄では evidence style の妥当性を別途問う。
- T7 は T5 の selected frames を流用せず、T6 後の final surface で同じ
  selected/exclusion positive control を再撮影する。
- T8 は mutation-control omission を "visual cleanup" としてではなく、Phase 7
  coverage citation で audit する。

### 後続タスク / オーナーへ共有すること

- **T6 へ:** `examples/gallery/gallery.ui` is now the T5 final Rust surface.
  Port it without changing tab/scroll/lightbox semantics unless a recorded
  host-port issue forces a deviation.
- **T7 へ:** T5 evidence is a precheck. Re-capture final selected/exclusion,
  lightbox open/closed, wrap/overflow, and aspect evidence after T6. Plan the
  authoritative capture as visible-desktop / outside-sandbox evidence, and
  treat the coordinate + `CopyFromScreen` harness as a known fragile
  dependency rather than a neutral detail.
- **T8 へ:** Cite Phase 7 collection/iteration coverage for omitted mutation
  controls during the no-silently-deferred-surface audit.
- **オーナーへ:** G(2) は通過済み。次に owner-facing な画像判断が必要になるのは
  T7 の G(3) positive-control confirmation。
