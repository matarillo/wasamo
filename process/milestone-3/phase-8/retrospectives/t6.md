## 目標・前提・計画仮説の再点検

> 後続タスクの retrospective でも流用するダブルループ振り返り欄。
> 実行の巧拙（シングルループ）でなく、**設定した目標・前提・事前計画
> （= 検証すべき仮説）自体が妥当だったか**を、反証可能な signal とともに
> オーナーと問い直す。下の 5 サブセクションがひな型。

### 観測された事実（反証可能な signal）

- `examples/gallery/gallery.ui` を変更せずに C / Zig hosts は build + render できた。
- `t6-parity-rust.png`, `t6-parity-c.png`, `t6-parity-zig.png` は同じ初期 Gallery
  view を示したが、selected/exclusion や lightbox transition は exercise していない。
- `feat/m3-phase-8-t6` に visible remote tracking branch は無く、push は別 gate。
  そのため remote CI run id は task-local close evidence としては取得しなかった。
- Zig は outside-sandbox build が必要で、local command 後に source dir へ
  `.zig-cache` を生成することが再確認された。

### 自己分析（どの層が外れたか）

- **良かった点:** T6 start gate で "default-view parity precheck" と
  "authoritative GUI evidence" を分けたため、T7 の full-review GUI evidence を
  T6 に飲み込まずに済んだ。
- **外れた点:** 初期 plan の end gate は remote CI run id を T6 の必須条件のように
  読めた。push が別 gate である運用と衝突するため、task 中に plan を実態へ
  修正した。
- **計画仮説の外れ:** `zig build -p ../../build/gallery-zig` なら source dir に何も
  残らない、という暗黙の期待は外れた。Zig は local `.zig-cache` を作るため、
  source-tree artifact check が必要だった。

### 計画仮説・前提の問い直し（オーナーと）

- **「T6 は three-host GUI evidence を閉じるか」** — 部分的に閉じる。
  初期表示 parity は T6 が閉じるが、positive-control state set は T7 が閉じる。
- **「Remote CI run id を T6 close に必須化するか」** — 必須化しない。
  CI YAML の追加と local rehearsal は T6、push/remote run id は owner gate /
  phase-end gate として扱う。
- **「C/Zig hosts は Gallery `.ui` を変える必要があるか」** — ない。
  T5 surface をそのまま port できたため、T6 は host templates と CI だけで閉じた。

### 反証可能な是正テスト

- Future host-port tasks should record whether remote CI is actually reachable
  before making a workflow run id a task-local close condition.
- Zig example tasks should check and remove source-local `.zig-cache` after
  every local Zig command before commit.
- GUI evidence split should be named at start gate: default-render parity vs
  positive-control behavior frames.

### 後続タスク / オーナーへ共有すること

- **T7 へ:** C / Rust / Zig hosts now exist and render the same default Gallery
  view. Re-capture the final positive controls; do not reuse T6 parity frames
  as selected/exclusion or lightbox evidence.
- **phase-end へ:** Remote CI run id is still open if no owner-approved push /
  workflow run happens before task merge.
- **オーナーへ:** T6 は local evidence では green。merge 前の別エージェント review
  では CI step ordering, host memory-load boundary, and T6/T7 evidence split を
  見てもらうのがよい。
