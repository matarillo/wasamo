## 目標・前提・計画仮説の再点検

> 後続タスクの retrospective でも流用するダブルループ振り返り欄。
> 実行の巧拙（シングルループ）でなく、**設定した目標・前提・事前計画
> （= 検証すべき仮説）自体が妥当だったか**を、反証可能な signal とともに
> オーナーと問い直す。下の 5 サブセクションがひな型。

### 観測された事実（反証可能な signal）

- T7 frames show All -> Albums -> Favorites selection movement, with the
  previously selected tab clearing in each transition.
- T7 frames show lightbox present -> absent, with `lightbox-closed` captured
  before the narrow/scroll pair.
- Narrow capture reflowed the thumbnail grid from nine columns to five columns,
  and Scroll down advanced visible labels from `IMG 001`-anchored to
  `IMG 006`-anchored.
- Independent review found no issues, but explicitly noted that aspect evidence
  is partly visual and partly citation-based.
- Claude review noted that T7 reused the T5 absolute coordinates verbatim; since
  T6 did not change `gallery.ui`, reuse was valid, but the provenance wording
  needed to say "re-validated and reused" rather than "freshly derived".

### 自己分析（どの層が外れたか）

- **良かった点:** Start gate で T5/T6 frames を precheck と切ったため、T7 は
  final post-T6 surface を再撮影できた。
- **良かった点:** T5 の coordinate miss learning を受け、state-confirming frame を
  T7 script の前提にできた。
- **計画仮説の修正:** T7 plan の "aspect evidence or T8 citation" は広すぎた。
  実際には "T7 Gallery visual + Phase 2 tests citation; T8 verifies public-draft
  reproducibility" という三点セットで表現するのが、証拠としても責務分割としても
  いちばん正確だった。
- **記録仮説の修正:** "coordinates are not retained ground truth" は「必ず新規に
  座標を測り直す」という意味ではなく、「surface unchanged を確認せずに過去座標を
  contract 扱いしない」という意味だった。T6 が `gallery.ui` を変えていないなら、
  re-validation + reuse が正しい閉じ方。

### 計画仮説・前提の問い直し（オーナーと）

- **「T7 は app を操作して owner smoke まで閉じるか」** — 閉じない。
  T7 は assistant-visible capture と G(3) owner confirmation まで。T10 が owner
  human-visible smoke を持つ。
- **「T7 画像は T5/T6 precheck を流用してよいか」** — 流用しない。
  T6 後の final surface で再撮影することが evidence の条件。
- **「Aspect は T7 だけで fresh comparison を作るべきか」** — 作らない。
  T7 は final Gallery の visible aspect surface を示し、already-landed tests を
  citation する。Public draft から reader が再現できるかは T8 の外部読者 smoke で
  検査する。

### 反証可能な是正テスト

- Future GUI evidence tasks should record, before capture, whether each frame is
  a state transition proof, a resize/scroll proof, or a citation-backed visual
  proof.
- Any multi-state capture script should insert a state-confirming frame after a
  modal/overlay close or any coordinate-sensitive click before moving to a new
  state family.
- T8 should explicitly ask whether `docs/dsl_spec.md` alone lets an external
  reader reproduce `Box.aspect` behaviour for Gallery thumbnails/lightbox.
- Future capture logs should record one of three coordinate provenance classes:
  fresh derivation, re-validation + reuse because the surface is unchanged, or
  rejected reuse because the surface changed.
