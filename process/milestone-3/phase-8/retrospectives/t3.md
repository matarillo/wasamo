# T3 レトロスペクティブ

タスクブランチ: `feat/m3-phase-8-t3`

T3 は Phase 8 implementation の **`ToggleButton` / `checked`
compiler + textual IR surface**。T1 の string-carried widget-kind recon
を受けて、`wasamoc` 側で `ToggleButton` を known widget として認識させ、
`checked` を `ToggleButton` 専用 bool attribute として admit/reject し、
既存の generic lower / emit path が literal / binding / `clicked` / alpha
block-assignment shape を textual IR へ運ぶことを fixture で固定した。

start gate / end gate は [../implementation/log.md](../implementation/log.md)
に記録済み。runtime loader / runtime widget node / visual state は T4 に残し、
T3 では project-wide unknown-widget warning policy を変更していない。

## 目標・前提・計画仮説の再点検

> 後続タスクの retrospective でも流用するダブルループ振り返り欄。
> 実行の巧拙（シングルループ）でなく、**設定した目標・前提・事前計画
> （= 検証すべき仮説）自体が妥当だったか**を、反証可能な signal とともに
> オーナーと問い直す。下の 5 サブセクションがひな型。

### 観測された事実（反証可能な signal）

- `wasamoc` lower / emit は `IrNode.widget_type: String` と generic prop /
  binding / handler lists をそのまま使うため、T3 の production code は
  `check.rs` に集中した。
- `cargo test -p wasamoc` と `cargo test --workspace` は、T3 の new fixtures を
  含めて green。
- T3 の初期 plan には "emit → load preserves" が残っていたが、loader は T4
  start condition にある runtime surface だった。

### 自己分析（どの層が外れたか）

- **良かった点:** T1 carry-over の warning-only hole を、実際の no-warning fixture
  に落とし込めた。generic path は production branch を増やさずテストで固定できた。
- **外れた点:** plan 仮説の "IR roundtrip" という語が loader responsibility まで
  含むように読めた。実装前の T3 responsibility cut で気付いたため、task 内で修正できた。
- **注意点:** `ToggleButton` unknown attr reject は Button の既存 loose path より
  少し強い。これは DD-001 の dedicated type / only-new-attribute に合わせたが、
  T4 loader mirror の見落とし余地を作る。

### 計画仮説・前提の問い直し（オーナーと）

- **「T3/T4 split は妥当か」** — 維持。T3 は compiler / textual IR、T4 は loader /
  runtime / visual。string-carried carrier のため、この分割の方がレビューしやすい。
- **「unknown widget warning-only policy を T3 で変えるか」** — 変えない。T3 は
  `ToggleButton` known admission を証明し、一般 policy は別判断として残した。
- **「`ToggleButton` unknown attr を reject するか」** — T3 では reject。accepted
  surface が `text` / `style` / `enabled` + `checked` に限定されており、未知 attr を
  通す方が T4 loader re-reject と public draft sync を弱くするため。

### 反証可能な是正テスト

- T4 start gate は、T3 の authoring catalog を loader catalog に写す項目を持つ。
- 次に "roundtrip" と書くときは、compiler-only roundtrip か loader roundtrip かを
  task bullet に明記する。
- 新 widget kind 追加時は、warning-only policy が残る限り no-warning fixture を
  required artifact として扱う。

### 後続タスク / オーナーへ共有すること

- **T4 へ:** `ToggleButton` textual IR は出るが runtime loader はまだ受けない。
  `resolve_prop_key` / validation / construct arm / visual node を、T3 の authoring
  catalog と同じ境界で閉じる。
- **T5 へ:** alpha tab-band shape は compiler/IR 上は通る。live exclusion / Gallery
  integration は T4 runtime completion 後に確認する。
- **オーナーへ:** unknown widget 全般の warning-only policy は今回も変更していない。
  将来 hard error 化するなら、T1/T3 の carry-forward を入力に別判断する。
