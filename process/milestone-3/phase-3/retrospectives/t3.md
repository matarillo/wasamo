## Main Learning

中心的な学びは **「T3 は progress doc preamble (Phase 3 introduces no
new IR variant) と framing decision の合致性を test として固定する
step だった」** という確認。production コードを 1 行も足さずに済んだ
こと自体が、Phase 3 の framing — 「WrapPanel は generic な
`IrNode` + 既存の `IrLiteral::Int` で表現できる」 — の正しさの
verification であり、test の役割はそれを regression として固定する
こと。

副次的な学び:

- **「absent attribute は IR から省略する」契約は test で明示しないと
  silent な regression のリスクがある**。`lower.rs` の `lower_node`
  実装は `Member::PropertyBind` を 1 件ずつ `props` に push するだけで、
  「未設定なら何もしない」のは構造的に自明 — しかし将来 default
  inference を IR 層に持ち込みたくなる変更圧力に対する gate が必要に
  なる。`only_item_cross_size_set_omits_other_attrs` test で
  `find_prop(w, "item-spacing").is_none()` を assert することで
  「runtime 側 T5 に default 解釈を委ねる」境界を test 上で見える化。

- **「parse → lower の end-to-end test」shape は T1/T2 の check-only
  test より検証範囲が広い**。tokenize → parse → check → lower の
  全段を 1 つの fixture で通すため、kebab-case ident 解析 (T1 lexer
  prerequisite)・WrapPanel 属性の i32 型付け (T1 catalog)・aspect-only
  Box warning が error として lower を block しない (T2 severity)
  などが暗黙に検証される。T3 の 6 件は lowering の最小 surface 検証
  でありつつ、上流 step の累積 regression coverage を兼ねる。

- **「Text {} を child に使った no-attribute test は T2 warning を
  避けるための意図的選択」**。`WrapPanel { Box { aspect: 1:1 } Box {
  aspect: 1:1 } Box { aspect: 1:1 } }` のような shape は T2 warning
  を発火させるが、warning は `has_errors()` を返さないので test 自体は
  通る。とはいえ test 意図 (lowering の検証) が他の relevant signal
  に紛れないよう、`Text {}` を使って warning surface を踏まない fixture
  に揃えた。

## Follow-Up

T3 から後続 task への明示的な引き渡し:

- **T4 (`wasamoc` IR text emit):** T3 の `WrapPanel` IR shape (`IrNode
  { widget_type: "WrapPanel", props: [IrProp { name, IrLiteral::Int }, ...] }`)
  は emitter の既存 `IrNode` / `IrProp` emit 経路にそのまま乗る見込み。
  emit 側にも「no new emit grammar」前提があり、kebab-case attribute
  名 (`item-cross-size` 等) を IR text にどう書き出すかは既存の prop
  literal position の string 表現 (Ident 経路) に従う。round-trip
  test で parse → IR → emit → parse の安定性を確認する。
- **T5 (`wasamo-runtime` widget catalog):** runtime 側で
  `WidgetData::WrapPanel { item_cross_size: Option<i32>, item_spacing:
  i32, line_spacing: i32 }` を materialise する際の IR loader 経路は
  「absent → default 適用」「present → 値を取得」の単純 dispatch。
  T3 で「absent は IR から省略される」契約を test 上で固定したので、
  loader 側はそのまま `props.iter().find(|p| p.name == "item-spacing")`
  パターンで実装できる。
- **T10 (Phase-end Moment 2 spec re-sync):** dsl_spec §4.10 と
  実装の整合は本 step で広がっていない (production コード変更なし)。
  Moment 2 でレビューすべき新規 factual gap は無し。
