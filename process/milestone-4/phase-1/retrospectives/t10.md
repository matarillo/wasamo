### 反証可能な是正テスト

- **plan 項目の陳腐化**: 以後の task で、着手時に §当該 task の各項目を
  「他 task の close でこれは既に閉じていないか」で検査する。
  **反証**: レビュアーが、既に閉じた risk を閉じることになっている
  項目を新たに見つけたら失敗。
- **control の "before" 定義**: 以後、比較を求める項目は
  「何と何を比べるか」を**両方名指し**しているか。
  **反証**: 比較対象の一方が未定義のまま実行段階に到達したら失敗。
- **良すぎる結果**: 「記録より良い結果」が出たとき、根本原因を
  追ったか。**反証**: 差分ゼロ・想定より小さい差分を、由来を特定せずに
  「安定している」と書いたら失敗。
- **「不可能」判定**: 以後、可能性を否定する記述に、**試していない
  経路の列挙**が同じ段落にあるか。**反証**: 列挙のない「できない」が
  landing し、後で別経路で可能だと判明したら失敗。
- **勝手に足した制約**: オーナーに選択肢を出す前に、**その選択肢が
  必要になった前提が仕様に書いてあるか**を確認したか。**反証**:
  仕様に無い自作の制約から組み立てた選択肢を、再びオーナーに投げたら失敗。
- **今回適用して効いた是正（記録）**: T9 の「危険を書いたら同じ段落で
  打ち消さない」。`SPI_SETLOGICALDPIOVERRIDE` の no-op が TRUE を返した
  時点で「たぶん動く」と書きたくなったが、**測っていないので
  「エントリポイントが存在する」しか書かなかった**。plan・log・
  本 retro の 3 箇所とも同じ書き方で揃えてある。**この規律は効いたのに、
  同じ run の中で「不可能」側には適用されていない** —— 「未測定を
  肯定側に書かない」は守り、「未測定を否定側に書かない」は守らなかった。
  規律が**片側にしか効いていなかった**ことが、今回いちばん具体的な発見。
