# T6 レトロスペクティブ

タスクブランチ: `feat/m4-phase-1-t6`

T6 は、テキスト面を window DPI のデバイス解像度で確保・描画し、
`CompositionSurfaceBrush` を 1 texel = 1 device pixel に固定した。また、
window に属する content tree の geometry scale と、実際に text surface を
rasterize した DPI を別 marker にした。production layout は
`WindowState::scale` を明示入力として全 geometry を一倍率で投影・commitし、
fallible な text refresh は独立して失敗 node の marker を stale のまま残す。
IR conditional / `for` で増えた subtree は scheduled layout で、direct tree
mutation は後のlayoutで正規化される。

## チェックリスト（task-end、項目 1〜11）

### 1. 今回の主な学び

**(a) atomic commit だけでは、異なる事実を1 markerへ畳む問題は解けない。**
元の plan は、1 回の再帰で brush を作りながら cache も更新する想定だった。
start gate で partial geometry cache を検出し prepare-then-commit に変えたが、
独立レビューはその第2案も反証した。root cache を target と freshness の両方に
使うと、`WindowState::scale` との乖離時に authoritative target を失い、text
failure が geometry pass を止める。最終形は geometry scale と last-rasterized
DPI を分離し、caller target で geometry を完了してから失敗 node の raster
marker だけを stale に残す。atomicity の単位は「tree全体」だけでなく、状態が
表す命題ごとに選ばなければならない。

**(b) synchronous message を期待する設計は、API successだけでなく
「期待したmessage内の処理完了」を観測しなければならない。** delta review は
`SetWindowPos` failure時に nested `WM_SIZE` がなく、authoritative scaleだけが
進む穴を検出した。さらにAPIが成功してもsize不変ならmessageがない。T7は
successful geometry passを明示的に記録し、未観測なら current client rect と
new scaleでstep 3を補完してからtext refreshへ進む。このfallbackはphysical
client extentを同じnew scaleでDIPへ変換してlayoutに渡す。Visual writeは逐次
なので失敗時に一部だけ進み得るが、cacheは全projection成功後だけcommitし、
fallbackはtree全体を再投影する。

**(c) 「100% なら不変」は、倍率演算だけを見た仮説だった。** D2D DPI と
atlas-origin conversion は 96 DPI で恒等だが、`ceil` による整数 surface
確保と DD-M4-P1-006 の `None` / top-left mapping は恒等ではない。親版と
T6 版は 96 DPI でも 6 枚すべて materially different で、brush setter だけ
を外した mutation でも 6 枚すべて変わった。予想と違う frame を退行として
押し戻さず、計画の「unchanged」を反証された命題として訂正できたのが重要。

**(d) GUI の before/after だけでは、正しい機構を特定できない。** 125% の
対は「小さくぼけた parent」と「client 全体に広がり、glyph の stem/counter
が改善した T6」を区別する。ただし複数の row-7 変更をまとめて観測するだけ。
そこで default-brush mutation と、live WinRT property を読む mock-free
integration test を追加し、`Uniform` / `0.5` と `None` / `0.0`、非比例な
source/destination、整数・小数 origin を別の positive control にした。

**(e) build freshness と source identity は同じではない。** 親 worktree と
task tree が同じ target を使った比較では、親を build した直後に task 側の
runtime が fresh と判定された。さらに mutation capture は、source を戻す
だけでは DLL を戻さない。比較 source tree ごとの target 分離と、mutation
後の package clean + accepted-source rebuild が必要である。最終 6 frame が
受入版 6 frame と client 内 byte-identical なのは特定のrender-changing mutation
からの復元controlであり、render-neutral mutationを含む一般のsource identityは
clean/rebuild記録またはstructural artifactで示す必要がある。

### 観測された事実（反証可能な signal）

事前 plan の二つの命題と、start gateで選んだ第2案が別々のsignalで反証された。
単一 fallible walk は中間失敗点を置くと mixed cache を作る。all-or-none
prepare-then-commit は、独立レビューの`WindowState::scale != root cache`
traceでauthoritative targetとraster retryを同時に失った。100% rendering
unchanged は fresh parent/T6 6-frame pair が全件 material difference を示した。
また byte-identical frame は特定のmutation残留を否定するが、render-neutral
source差分までは否定しない。

### 自己分析（どの層が外れたか）

外れたのは API 選択ではなく、**責務モデル**と**証拠モデル**。責務モデルは
成功時の最終 tree だけを見ており、O(text nodes) の途中失敗と incremental
attach を含めていなかった。start gateでpartial commitは止めたが、geometry
scaleとlast-rasterized DPIを同じcacheで表す前提までは問い直せず、独立レビュー
が止めた。証拠モデルは「倍率 1 = 全操作が恒等」とまとめ、ceil と brush
mapping を DPI conversion から分離していなかった。

### 計画仮説・前提の問い直し（オーナーと）

T6 の目的を「DPI 引数を text renderer に通すこと」と狭く置くべきでは
なかった。出荷される責務は、window content tree のgeometryをauthoritative
window scaleで一様に書き、その後のtext failureを「surfaceも更新済み」と
誤記録しないこと。成功時は両者が収束し、失敗時はgeometryを止めずraster
markerだけがretryを保持する。initial attach と incremental attach を同じ
boundaryで覆う現在の責務が妥当だった。一方、直接 Composition visual を足す
`window_add_widget` まで
暗黙に含めると retained root のない別 API を再設計するため、明示 limit の
ままが妥当。将来この API が content root を保持する時点が再検討 signal。

### 反証可能な是正テスト

後続の tree-wide fallible operation は、approach 選択前に「先頭成功、途中
失敗、末尾未実行」の状態表を書き、authoritative / derived data の各 writer
が何を残すかを確認する。GUI の「倍率 1 では不変」は、変更操作を列挙し、
各操作が本当に identity かを別々に判定する。cross-tree / mutation evidence
は source tree、artifact directory、build command、最終 accepted rebuild を
4 点セットで記録する。frame比較はrender-changing mutationのcontrolとして
使い、一般のsource identityへは拡張しない。

### 後続タスク / オーナーへ共有すること

T7 は production geometry entry に `WindowState::scale` を渡し、nested
`WM_SIZE` では通常の post-layout text refresh を抑止して、`SetWindowPos`
return 後の step 4 で独立 refresh primitive を呼ぶ。nested geometryの成功を
観測できなければ physical current client rectをnew scaleでDIP化してstep 3を
whole-tree fallbackし、成功後だけstep 4へ進む。projection失敗時はVisualが
部分更新済みでもcache/markerを進めず、再試行可能な失敗としてlogする。
geometry cache とraster markerは既に分離済みなので、surface failureは成功済み
geometryを戻さず、失敗nodeのmarkerだけがstaleに残る。
T8 は legitimate attach path では stale descendant を作れないので hidden seam
を使う。T10/T12 は F-40 の target isolation と accepted rebuild を evidence
手順として実行・同期する。別エージェントの full review と correction-only
narrow review はzero-major / zero-minorまで閉じた。実
Compositor-unavailable guard発火も3/3観測済みで、T6 task gateは完了した。
mergeは別gateなので、オーナーの明示承認前には行わない。
