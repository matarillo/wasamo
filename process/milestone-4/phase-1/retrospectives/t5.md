# T5 レトロスペクティブ

タスクブランチ: `feat/m4-phase-1-t5`

T5 は境界で DIP ↔ 物理を変換し、それ以外では変換しない task。倍率 1 では
全部恒等なので、出荷される見た目は変わらない —— それが「見える退行でなく、
レビュー可能なコミット」として着地できる理由でした。

plan が名指ししていた未決の論点 3 件が本体:

- **監査行 5 / 6 の `SetOffset` に使う操作**: 成分ごとの `to_physical`。
  `DipScale` に「すでに親相対の対」用の操作は**足さない**。
- **`visual_rect` の readback を割る倍率**: **ノードのキャッシュ**。
- **callback slot 6 個の単位**: **DIP**。ポインタ 4 個は `i32` → `f32`。

start gate / close gate は
[../implementation/log.md](../implementation/log.md) の T5 entry。
close gate の中心は四つ: **編集前に登録した「座標を運ぶ API 面」の列挙**と
それに対して組んだ **13 行の呼び出しサイト監査**、**14 行の副作用列挙**、
**trap #3 の「源を書き換えるものは誰か」表**、そして **種類の違う 2 つの
GUI 証拠**（バイト一致の回帰セットと、125% で判別力のある撮影 + その変異）。

## チェックリスト（task-end、項目 1〜11）

### 1. 今回の主な学び

四つ。

**(a) 「予測された数字」は、この phase で唯一手に入る判別力のある証拠
だった。** T5 の実質ゲートは監査表、というのが plan の想定で、それは
正しい。ただし plan 自身が **T4 の時点で「T5 が動かす数字」を書いていた**
—— aware + 補正の状態はタイル 9 個で、「inbound seam が着地したら 7 に
戻らなければならない」（F-27）。throwaway の宣言を 1 行足すだけで、T9 を
待たずに 125% でその数字が読める。実測 **7**。inbound の除算を外すと
**9** に戻る。倍率 1 の世界では原理的に作れない対照が、**plan の中に
すでに書いてあった**わけです。「T5 の証拠は監査表 + 緑のスイート」という
T1 の見立ては、当時としては妥当でも、予測の存在を勘定に入れていなかった。

**(b) 撮影して初めて「T5 が出荷する状態」の見え方が分かった。**
ノードのキャッシュを書くのは T6 の walk なので、T5 単体では outbound が
恒等 —— つまり **125% のクライアント領域の 80% にしか描かれない**。
正しい挙動ですが、これを知らずに T6 や T10 でこの撮影を見た人は不具合と
読むはずです。キャッシュを throwaway で 120 DPI に seed すると全面に
広がり、タイルは 7 個のまま、文字だけがぼけたまま —— R-1 の前提が議論では
なく画として出た形。plan §T10 に「T5 と T6 の間の撮影はこう見える」を
書きました。

**(c) 監査クエリを「編集前に」書くと、それ自体が別種の artifact になる。**
R-8 の指摘は「差分から組んだクエリは、忘れたものを反証できない」でした。
今回は座標を運ぶ API 面を **start gate で**列挙してから編集に入ったので、
「`MoveWindow` も `AdjustWindowRect*` も `ClientToScreen` も
`GetSystemMetrics*` もリポジトリに存在しない」が、後付けの言い訳でなく
手順の帰結として言えます。これは T4 のときレビュアーがやってくれた作業を
先回りしたというより、**やる順番を変えただけで artifact の強度が変わった**
という話です。

**(d) 命題で伝播すると、文字列では絶対に届かない場所に届く。**
T4 の差分レビューが根因を特定した規律の初回運用でした。効果は即座:
命題 Q5（アトラス原点は実質 `(0,0)` にならない）の 3 番目の主張箇所は
**規範スペック `architecture.md` §12.4**、命題 Q6（撮影時のコミットを
確認すれば流用してよい）の主張箇所は **ADR セットの検証項目 3 と
`constraints.md` §9**。後者は F-33 の文言と共通語が 1 つもありません
（向こうは「証拠を撮った時点のコミットとの差分を確認する」）。さらに
命題 Q7 で、F-26 が T4 に plan §T5 を直したのに **implementation
preamble の obligation 4 が直っていない**のを検出しました —— S-3 の形の
4 回目を、レビュアーでなくこちらが見つけた形です。
