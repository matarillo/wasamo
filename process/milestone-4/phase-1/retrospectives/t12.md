### 観測された事実（反証可能な signal）

- T12 の責務は landed state と概ね一致したが、F-33 の owner decision だけが
  古かった。ADR/constraints へ注記する pending choice ではなく、Observation 4
  だけを直す決定済み事項だった。start gate 前に plan を訂正できた。
- 「AGENTS の build-order claim を直す」という 1 項目に対し、現行の利用者向け
  surface は少なくとも README 6、CMake 3、Zig usage 3、人手 smoke 1 を同じ
  命題で主張していた。名指しファイルだけの修正では監査を通らなかった。
- documented order を守った cold debug / release の両方で F-54 は再現した。
  したがって warning 自身が提示する remedy は、その warning を消す条件では
  ない。workspace build はその後成功した。
- 指定された CMake は version 4.3.1-msvc1、Microsoft の有効な署名、help 上の
  default は VS17、PATH 未登録だった。`build/gallery-c` の cached VS18 generator
  は instance を解決できなかったが、明示した fresh VS17 directory は同じ
  executable で configure/build に成功した。

### 自己分析（どの層が外れたか）

- plan の task boundary と Moment 2 の対象選定は妥当だった。T1〜T11 が材料を
  数値・再発条件・owner decision まで積んでいたため、T12 は再推論せずに
  claim owner へ同期できた。
- 外れたのは、ビルド順序の訂正面を当初 `AGENTS.md` 中心に見ていたこと。
  ユーザーから明示された「訂正した命題を 1 文で書き、主張文書を列挙する」
  手順を実行して初めて、実利用手順の広がりが見えた。grep の文字列ではなく
  命題の列挙が load-bearing だった。
- CMake の最初の failure を見た時点で「新しい directory が VS18 を自動選択
  した」と途中報告したが、`cmake --help` は VS17 を default と示した。
  永続記録では cache/generator state と executable default を分離して訂正した。
  failure output だけから tool の選択規則を推定したのが誤りだった。
- Normal review で、命題監査の表自身が `preamble.md` の live risk table を
  列挙から落としていたことが判明した。README 群まで広げても、常時参照される
  phase risk table を落としていれば「命題で探した」とは言えない。レビューで
  R-1b の workspace-only remedy を発見し、表と本文の両方を訂正した。

### 計画仮説・前提の問い直し（オーナーと）

- **Moment 2 の sync 対象を plan にファイル名で列挙するだけで十分か。** 今回の
  answer は no。規範文書の一覧は ownership を示すが、同じ命題を利用者へ
  伝える operational surface の一覧にはならない。今後も plan の named files
  を起点にしつつ、命題ごとの claim-site audit を close artifact にする。
- **F-54 をいつ直すか。** Phase 1 の成果を否定する failure ではなく、build は
  green で、T12 で branch を直すと diagnostic/test-focused review lane の追加
  作業になる。現時点では handoff の trigger で十分。次に rust-sys / cdylib seam
  を触る時、warning を削るだけでなく dependency/build-script timing を再監査する。

### 反証可能な是正テスト

- 文書訂正前に、訂正命題を 1 文にし、規範・運用・index/handoff の claim sites
  を表にする。**反証**: 次回、表にない現行手順が同じ古い命題を主張していたら
  この是正は効いていない。
- tool の generator/default を主張するとき、failure output に加えて tool 自身の
  `--help` と build-directory cache を別々に読む。**反証**: 次回、cache の値を
  executable の default として記録したら効いていない。
- build warning の remedy を採用する前に、その remedy を実行した cold build で
  warning が消えるかを見る。**反証**: 実行後も同じ warning が出るのに、同じ
  root cause として close したら効いていない。

### 後続タスク / オーナーへ共有すること

- `wasamo.dll.lib` を生成する package は `wasamo-dll`。一方、F-5/F-21 の回避に
  primary build が必要なのは uplifted rlib の owner `wasamo-runtime`。この 2 つを
  取り違えないこと。
- CMake の指定パスは利用可能で署名も有効。ただし PATH にはないため、今回の
  gate は絶対パスを使用した。generator cache が壊れている/別 instance を指す
  directory では、fresh directory と明示 generator で tool 自体と cache を
  切り分ける。
- phase-end batch は未実施。T12 が完成させたのは implementation task 群までで、
  CI、handoff finalization、phase retro、phase→main gate は次の別作業。
