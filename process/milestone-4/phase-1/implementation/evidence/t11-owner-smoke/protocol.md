# T11 オーナー目視 smoke — 実施手順

この phase の GUI ゲートは毎回スクリプトが手順の記録も兼ねていた。T11 は
人が実施するので、その代わりがこの文書になる。実施前に確定させたものであり、
結果は [../../log.md](../../log.md) §T11 に記録する。

日本語なのは、オーナーが実行するため。記録側（log.md）は英語のまま。

## 何を見る task なのか

別倍率のモニタをまたいだとき、論理レイアウトが保たれ、文字が移動先の解像度で
描き直されるか。合成メッセージ（T8）でも、同一モニタでの倍率変更（T10
control C）でも届かない、現物のモニタ越えだけが残っている。

## 前提

- ノート PC 内蔵 **150%**、外部ディスプレイ **100%**。
  **ホストを起動する前に**設定しておく。
- 配布セット（`gallery-zig.exe` + `wasamo.dll`）が展開済みで、2 つが同じ
  ディレクトリにあること。
- 事前に 1 回だけ `gallery-zig.exe` をダブルクリックし、窓が出ることを確認する。
  出ない場合はほぼ Visual C++ 再頒布可能パッケージの不足。モニタ配置を整える
  前にここで潰す。

## やらないこと

- **窓のサイズを変えない。** 物理サイズと枠の太さも観測対象。
- **またぐ瞬間を注視しない。** 人の目では判定できないと判断し、この task の
  範囲から外してある（理由は log.md §T11 の再監査 1）。移動が**終わってから**見る。
- **配布ファイルを差し替えない。** 対照は同じバイト列の 2 回実行であることに
  価値がある。

## 手順

### leg 0 — 内蔵 150% での基準

1. 内蔵ディスプレイ側で `gallery-zig.exe` を起動する。
2. タイルが 1 行に何枚並んでいるか数える。
3. 文字（タイルの説明文、タブのラベル）がにじんでいないか見る。
4. 撮影 → `1-internal-150-aware.png`

### leg 1 — 外部 100% へドラッグ

5. タイトルバーをつかんでドラッグし、外部ディスプレイへ移す。
6. 落ち着いてから見る:
   - 1 行のタイル枚数は leg 0 と同じか
   - 文字が移動先でも鮮明か
   - 窓の物理サイズが変わったか（変わるのが正しい）
   - タイトルバーと枠の太さが移動先の倍率になっているか
7. 撮影 → `2-external-100-aware.png`

### leg 2 — 移動先での操作

8. タブ（All / Albums / Favorites）を切り替える。ボタンにカーソルを乗せる。
   クリックとホバーの反応位置がカーソルとずれていないか見る。
9. 撮影（任意）→ `7-external-100-clicked.png`

### leg 3 — 戻す

10. 内蔵ディスプレイへドラッグして戻す。leg 0 と同じ見え方に戻るか。
11. 撮影 → `3-internal-150-restored.png`

余裕があれば、`Win+Shift+←/→` でのモニタ間移動も 1 往復してみる。シェル側の
経路が違うだけで同じハンドラに入るので、安いわりに範囲が広がる。

### leg 4 — 陽性対照（倍率を認識しない双子）

正しい実装と見分けのつかない偽物を並べる。倍率非対応の窓は移動先で同じ物理
サイズに引き伸ばされるので、**大きさでは見分けられない**。見分けるのは文字の
にじみと、プロセスの申告レベル。

12. 展開先ディレクトリで PowerShell を開き:

    ```powershell
    $env:__COMPAT_LAYER = 'DPIUNAWARE'
    .\gallery-zig.exe
    ```

    対応版のほうは、別のシェルかエクスプローラーからのダブルクリックで起動する
    （環境変数を設定していない親から起動する必要がある）。
13. **150% モニタ上で 2 つを並べ、1 枚に収めて撮影** →
    `4-internal-150-side-by-side.png`
    期待: 非対応版の文字がにじむ。
14. 2 つとも外部 100% へ移し、同じように並べて撮影 →
    `5-external-100-side-by-side.png`
    期待: **差が消える**。100% では変換が恒等なので、ここで一致することが、
    150% での差が倍率認識の差であることの裏づけになる。両方で差が出た場合は
    「2 つの何かが違う」以上のことが言えないので、そのまま記録する。
15. **姿勢を読み戻す。** タスクマネージャー →「詳細」タブ → 列見出しを右クリック
    →「列の選択」→ **DPI 認識** を追加。`gallery-zig.exe` が 2 行並び、値が
    違うことを確認する（表示名はビルドで変わるので、片方が「認識しない」相当で
    あればよい）。撮影 → `6-taskmgr-dpi.png`

    環境変数を設定したこと自体は根拠にしない。設定と、実際にそうなっていることは
    別の事実（T9 で一度これを取り違えている）。

## 撮影の要領

- Snipping Tool（`Win+Shift+S`）のウィンドウモード、または `Alt+PrtScn`。
- PNG のまま持ち帰る。再圧縮の入る経路を通さない。
- ファイル名は上記のとおり。このディレクトリ（`t11-owner-smoke/`）に置く。

## 記録して返すもの

1. 各モニタでの **1 行あたりのタイル枚数**
2. 各 leg の見え方（鮮明か、レイアウトが保たれたか、枠が追随したか）
3. 操作（クリック・ホバー）のずれの有無
4. 対照の結果（150% で差が出たか、100% で消えたか）
5. 手順どおりに実施できなかった項目があれば、そのこと

画像は assistant が中身を見て解析を書き、log.md §T11 に判定として残す。

## 後片付け

- 対照に使ったシェルを閉じる（または `Remove-Item Env:__COMPAT_LAYER`）。
- 倍率を普段の設定に戻す。
