# M4-Phase 1 — Handoff

> **Status: recorded (phase-end 2026-08-04).** Distilled from the T1–T12
> carry-forward ledgers and the phase-end audit in [log.md](./log.md), per
> [workflow.md](../../../procedures/workflow.md) and
> [retrospectives.md](../../../procedures/retrospectives.md). Items below are
> either durable handoff obligations or explicitly classified local residue;
> they are not phase acceptance claims.

## Main learnings

The phase's durable lesson is that DPI correctness is a chain of boundaries,
not a single scale-factor assertion: the host declares awareness, the window
owns one authoritative scale, layout consumes DIP client extent, composition
receives physical geometry, and raster allocation follows the same scale.
Evidence had to pin both the input and the output and include a positive
control; a green test or a plausible screenshot alone was insufficient.

The other durable lesson is operational: Cargo's primary-package artifact
selection affects which runtime code a DLL archives, and a cold test-only
selection is a different failure from a cold workspace build. Build order and
source identity therefore belong in every later GUI evidence gate.

| **The window's logical size is realised on the *outer* rectangle; the client rectangle does not follow by the same factor** (T4, measured) | Every evidence gate that compares layout across scales, and any future client-size `WindowConfig` attribute (M4-Phase 8 / AC11) | Any check that treats a DIP client size as derivable from the DIP outer size. Measured at 125%: 800 DIP outer is exactly 1000 physical, while the client is 785.6 DIP rather than 784, because the non-client frame scales by its own DPI-indexed system metrics rather than by `s`. | **A test that does OS work before its skip guard must not treat that work as certain to succeed** (T9 finding F-49, measured by the owner's guard-verification run) | Every Windows integration binary that needs OS state established *before* `wasamo_init` | `dpi_awareness_tolerated_failure_integration.rs` sets the process's DPI awareness before the shared helper's Compositor-unavailable skip decision, because it must precede `wasamo_init`. The first version `expect`ed that call to succeed — reasoned, not measured — and on the owner's session it returned `ERROR_ACCESS_DENIED` (the awareness was already set before any test code ran), so the binary **failed on exactly the environment where every other binary skips**. Same on-disk executable as every local run, so the cause is environmental; the mechanism is **not identified** and is not claimed. *Re-trigger:* any new test that must touch the OS ahead of the guard. The shape that works: attempt it, **discard the result**, read back the state actually in force, and put every assertion behind the guard — so the test asserts what is true rather than what it arranged. **The deeper re-trigger is the reasoning pattern, not the API**: this plan had already named the hazard ("this binary does OS work outside the guard") and then predicted it away in the same paragraph. | **An unaware observer cannot measure an aware window's rectangle** (T9 finding F-48, measured by getting it wrong first) | Every assistant-side or tooling-side measurement of a Wasamo window from T9 onward — **T10 immediately** | A DPI-unaware process asking `GetWindowRect` / `GetClientRect` about an aware window is answered in **virtualized** coordinates: the real rectangle divided by the system scale. | **A committed frame set is not a later task's baseline, and one capture is not a baseline** (T5 finding F-33, measured) | Every GUI evidence gate — T6, T10 — and later milestones that read [verification-environments.md](../../../../docs/notes/verification-environments.md) Observation 4 as procedure | Any comparison of rendered frames across builds. At the *identical commit*, two settled captures a day apart differ by 25 of 827,904 pixels and a session's **first launch** differed from its own second and third by 149, at up to 13 per channel. **Classified rather than described**: every differing pixel is a text pixel, no tile fill or background moves, and **not one flips between background and covered**, so the coverage mask is identical and only the intensity of already-covered pixels changes. Antialiased pixels differ; **antialiasing is not established as the cause**. Checking the commit the evidence was captured at — the procedure the ADR set's verification-closure item 3 and [constraints §9](../requirements/constraints.md) state — is necessary and **not sufficient**. Agree **multiple captures on each side** of the change. **The residual has a decision rule, measured rather than described**: every differing pixel was a text pixel and **not one flipped between background and covered**, so the coverage mask is identical and only the intensity of already-covered pixels moves, bounded at **13 per channel**. **The max per-channel delta is asymmetric evidence, and only that.** A **large** delta proves only that the difference is **outside the drift bound this phase measured** — not what caused it, since an intensity-only defect can exceed it too and the drift's own mechanism is unidentified. A **small** delta proves nothing, because (i) a rasterization defect changes intensity without moving geometry — a wrong D2D context DPI is exactly that, i.e. **T6's defining failure would read as drift**; (ii) a sub-pixel positional error need not flip any pixel between covered and uncovered; and (iii) contrast belongs to the edge, not to the change, so a geometry move across two near colours gives a small delta. "Palette-independent" was false. [evidence/compare-frames.ps1](./evidence/compare-frames.ps1) therefore **exits non-zero on any difference by default** and reports the delta as information; `-AllowDrift` opts into treating a small-delta difference as a pass, which is a judgement the runner records rather than a default a gate inherits. Atlas packing was instrumented and **ruled out** as the mechanism; nothing else is claimed, which is why a drift-only result is recorded with its numbers rather than filed as a clean pass. **Concrete instance left by this phase**: T3's committed `evidence/after/` is stale for two frames — the F-23 fix changed `labelupdate-clicked` and `-clicked-twice` by 30,800 px each — so reusing it as "the last known-good set" reports a regression that is not one.
