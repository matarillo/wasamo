# M4 題材アプリの仕様 — 写真ギャラリー成熟（A）+ 思いつきメモ（B4）

M4 の題材アプリ（target app）を確定する文書
（[workflow](../../procedures/workflow.md) §1.2 の成果物）。
[framing.md](framing.md) §次の一手 1 が指す着地先であり、方針固めで
確定した採択を**アプリの仕様として明文化**する。

**本書と framing.md の役割分担**:

- **framing.md が正本**なもの — M4 主眼の読み、機能リストと優先順位、
  各機能の粒度の定義、題材アプリの判断基準、M4 に入れないもの。
- **本書が正本**なもの — 採択の明文化（採用理由・2 本の役割分担）、
  各アプリの画面と操作、M4 が開く機能面の一覧、アプリ側の範囲外、
  B4 採択で生じた 2 つの上限、達成条件（AC）改訂の差分案。

本書は「どの機能を M4 でやるか」を決め直さない。それは framing で
確定済みであり、本書は「その機能を**どのアプリのどこが**本筋として
証明するか」を固定する。

---

## 採択

**M4 の題材アプリ = A（写真ギャラリー成熟）+ B4（思いつきメモ）の
2 本立て**を採用する。

| 案 | 内容 | 採択 | 役割 |
|---|---|---|---|
| **A** | 写真ギャラリーの成熟（M3 の継続） | framing F6（2026-07-09） | 初期フェーズの消費者。M3 で先送りした事項の消化を優先し、自然な範囲に留める |
| **B4** | 思いつきメモ（リストごとの複数ウィンドウ、完了状態なし） | framing F8（2026-07-27） | 後段フェーズの消費者。文字編集 / IME・複数ウィンドウ・最前面の重ね表示・ウィンドウ設定プロパティを本筋として証明する |

落選 3 案（付箋・設定画面の再現・チャット）は
[target-app-wireframes.html](target-app-wireframes.html) に歴史的記録
として残る。本採択により候補集合から外れる。

**2 本立てである理由**: 1 本のアプリに M4 の全機能を背負わせると、
どの案でもどこかに作為が入る（ギャラリーに検索欄を足して文字入力を
証明する、設定画面に不自然な別ウィンドウを足す、など）。2 本の組は
この作為を除去し、各機能を「アプリの本筋」として証明できる側へ
割り付ける。カバレッジは 1 本で背負わず 2 本の組で満たす。

---

## 採用理由

### A（写真ギャラリー成熟）

1. **M3 の残務を最も安く消化できるのは A 自身である。** M4 に持ち越した
   残務群（実画像・サムネイルの位置判定・ホイール / ドラッグでの
   スクロールと実スクロールバー・ライトボックスのモーダルフォーカス・
   動的な件数表示）はいずれも M3 のギャラリー画面に対する残務であり、
   別のアプリに載せ替えると残務ではなく新規作成になる。
2. **初期フェーズ（イベント配送・フォーカス・クリック処理・述語式）の
   消費者として、既に動く画面が手元にある。** 土台の設計を、新しい
   アプリの立ち上げコストと混ぜずに検証できる。
3. **M3 で先送りした DSL 面の再開条件が A で発火する。** 項目ごとの
   ハンドラ・ループ外からの collection 読み取り・項目ごとの条件表示・
   等値選択の軸は、いずれも A の具体ケース（サムネイルクリック・
   件数表示・キャプションの添字読み・選択中サムネイル）で自然に
   発火する（[framing.md](framing.md) §粒度の定義〔M3 先送り事項の
   吸収〕）。

### B4（思いつきメモ）

第二アプリが担うべき分（§2 本の役割分担）を、本筋としてどれだけ
自然にカバーできるかで選んだ。判断の経緯は
[framing.md](framing.md) §オーナーへの問い Q2、重み付け読みの記録は
[target-app-wireframes.html](target-app-wireframes.html) が持つ。要点:

1. **第一基準（担当分のカバレッジ）で穴がない。** 一行の入力欄への
   日本語入力が中心操作であり、1 リスト = 1 ウィンドウ、項目行の
   「…」メニュー、リスト名 + 件数の動的タイトル、項目行から開く改名
   ダイアログが、いずれも作為なしに成立する。
2. **第一基準で同格だったチャット案との差は副次基準で付いた。** 工数が
   同程度のため実質は「構造リスク」と「訴求力」の 2 軸となり、**構造
   リスクの低さを訴求の動きより重く取った**（framing F8）。B4 の項目は
   文字列の並びに留められるため、チャット案が抱える並行配列の圧力
   （`TypedValue` / 構造化された項目データの保留に接近する）を M4 に
   持ち込まない。
3. **複数行の文字編集を要求しない。** 付箋案が要求した「複数行を中核
   並みに引き受ける判断」を伴わないため、複数行の行は「載れば取る」の
   建て付けのまま維持できる。

**この採択が買ったもの（＝守るべき制約）**: 2 の「低い構造リスク」は
仕様の側で守らないと失われる。§B4 の 2 つの上限がその明文化である。

## 2 本の役割分担

機能ごとの担当。「担当」列のアプリが**本筋として**証明し、もう一方は
その機能を持たない（持てるが持たない場合は理由を記す）。

| 機能 | 担当 | 証明の形 |
|---|---|---|
| フォーカスモデル + イベント配送（基本形） | A → B4 | A で Tab 移動・クリック配送の土台を固め、B4 で異種部品を横断する密度を足す |
| 入力処理（キーボード / マウス / タッチ） | A（+ B4） | A のスクロール・クリック・キー操作。タッチの証拠形は該当フェーズの計画で決める |
| 汎用クリック処理（Button 以外へのハンドラ） | A | サムネイルクリック → ライトボックス。項目ごとのハンドラ（item / index 参照）の最初の具体ケース。B4 の項目行クリックは同型の再利用 |
| 単一行の文字編集 + IME（TSF） | **B4** | 一行の入力欄への項目入力と、改名ダイアログでの編集。A は入力欄を持たない |
| 複数ウィンドウ | **B4** | 一覧ウィンドウ + リストごとのウィンドウ。ウィンドウごとの collection とフォーカス |
| 最前面の重ね表示（構造 + 閉じ方の規則一式） | **B4** | 項目行の「…」メニュー。一覧の内部から開くため最前面層が構造的に要る |
| 閉じ込め（モーダルなフォーカス範囲）× ZStack | **A** | ライトボックス（ZStack のまま）。Esc・← → を含む |
| 閉じ込め × 最前面層の組合せ | **B4** | 項目行の「…」→ 改名ダイアログ。閉じ込め × 最前面層 × 文字入力 × IME を 1 か所で実証 |
| ウィンドウ設定プロパティ（動的タイトル / 初期サイズ） | **B4** | リスト名と件数がタイトルに出る。A は担わない（理由は §A が持たないもの） |
| ホスト状態境界 — 供給・差し替えの方向 | **A** | 写真 collection のホスト供給と、ホストによる差し替え |
| ホスト状態境界 — 書き戻しの方向（双方向束縛） | **B4** | 追加・改名・保管の結果をホスト側へ書き戻す |
| 述語式（件数・空判定・添字読み・等値選択） | **A** | 件数表示・ライトボックスのキャプション・選択中サムネイル |
| AccessKit / UIA | A + B4 | A で基本の役割付け、B4 で異種部品（一覧・入力欄・ボタン・項目行・メニュー・ダイアログ）を横断する読み上げ順序 |
| Mica / Acrylic + アクセント色 | A + B4 | アプリの絵柄に依らないため両方に載る（非差別化） |
| モニターごとの DPI 対応 | A + B4 | 同上（非差別化）。IME 候補ウィンドウの座標橋渡しは B4 側で交差する |
| `Image` 部品 / `fill` の直値指定 | **A** | 実画像のサムネイルとライトボックス。B4 に出番はない |
| 複数行の文字編集（載れば取る） | — | どちらの本筋でもない。取り込む場合の置き場は B4 だが、B4 の設計はこれを前提にしない |

## アプリ仕様 A — 写真ギャラリー成熟

### 画面

見た目の正本は M3 の
[gallery-wireframe.html](../../milestone-3/requirements/gallery-wireframe.html)
を**継続**する。M4 で新しいワイヤーフレームは起こさない（画面の骨格は
変わらず、変わるのは中身が本物になることと操作が効くことである）。

- 既定状態 — 上部のタブ列（All / Albums / Favorites + 右寄せの表示
  切替）、サムネイルの折り返し格子（WrapPanel × ScrollView）、
  下部のステータスバー（`218 photos`）。
- ライトボックス状態 — ZStack + 条件表示で重ねる。全面の暗幕、中央の
  写真、キャプション（写真の名前とメタ情報）、左右の送りボタン。

### M3 から加わるもの

| 加わるもの | 中身 |
|---|---|
| 実画像 | placeholder（Box + Text）を実際の画像に置き換える。`Image` 部品と `fill` の直値指定を伴う |
| スクロールの実体 | ホイール / ドラッグでのスクロールと実スクロールバー（M3 は clip + オフセット束縛のみ） |
| サムネイルの位置判定 | クリック位置からどのサムネイルかを解決する。汎用クリック処理の入口 |
| ライトボックスの操作 | サムネイルクリックで開く、Esc で閉じる、← → で前後、モーダルなフォーカス範囲による閉じ込め |
| キャプションの中身 | 選択中の写真の名前（collection の添字読み） |
| 動的な件数表示 | ステータスバーの件数。静的な Text と束縛された数値の並置で書き、文字列連結を式言語に持ち込まない |
| 選択中サムネイルの区別 | 等値選択（述語式が持ち込む `==`）による排他選択 |
| ホストからの供給・差し替え | 写真 collection をホストが供給し、ホストが差し替えると表示が追随する |
| Mica / アクセント色 / DPI | アプリ非依存の基盤面が A の画面にも載る |

### A が持たないもの（理由の記録）

M3 のワイヤーフレームどおり、**検索欄・別ウィンドウのビューア・
コンテキストメニューを持たない**。したがって A は次を担わない:

- **文字編集 / IME** — 検索欄を足せば載るが、それは「文字入力を証明
  するために足した欄」であり作為になる。B4 が本筋として証明する。
- **複数ウィンドウ** — 別ウィンドウのビューアを足すのは同様に作為。
- **最前面の重ね表示** — ライトボックスは根に宣言され、脱出すべき
  clip / 重なり順の境界を持たない。最前面層へ載せ替えると「何も脱出
  しない Portal」という退化した使い方になる。ZStack + 条件表示という
  規範スペックの生きた実例を温存する側を採る。
- **ウィンドウ設定プロパティ（動的タイトルを含む）** — 単一ウィンドウの
  ギャラリーにタイトルを動的化する自然な出番がない。(a) 同一ウィンドウ
  内のモーダル表示でタイトル（タスクバー / Alt+Tab / 読み上げにおける
  ウィンドウの同一性）を切り替えるのは UX 慣習に反し、それが買う DSL 面
  （添字読み）はライトボックスのキャプションで同等に取れる。
  (b)「Gallery — N photos」型のタイトルは文字列連結（式言語の範囲外）か
  ホスト合成の往復を要する。件数の動的表示はステータスバーが担う。

## アプリ仕様 B4 — 思いつきメモ

短い思いつきを溜める、**完了状態を持たない**書き留め用のアプリ。
視覚の正本は
[候補節のワイヤーフレーム](target-app-wireframes.additional.html)。

### 画面

3 種類のウィンドウと 2 種類の重ね表示からなる。

1. **一覧ウィンドウ（Lists）** — 開けるリストの一覧。各行は
   **リスト名のみ**と「…」メニュー・Open ボタンを持つ。下部に
   「＋ 新しいリスト」。
2. **リストウィンドウ（1 リスト = 1 ウィンドウ）** — 上部に一行の
   入力欄 + Add ボタン、下に項目行の一覧（ScrollView × 繰り返し生成）、
   下部にステータスバー（件数）。タイトルは「リスト名 — N items」。
3. **項目行の「…」メニュー**（最前面層） — `Rename item…` / `Archive`。
4. **改名ダイアログ**（最前面層 + 閉じ込め） — 項目行の「…」→
   `Rename item…` で開く。一行の入力欄 + Save / Cancel。
5. 一覧ウィンドウの行の「…」メニュー — `Rename list…` ほか。項目行と
   同じ形を再利用する。

### 操作

| 操作 | 経路 | 証明する面 |
|---|---|---|
| 項目を追加 | 入力欄に日本語で入力 → Add（または Enter の扱いは該当フェーズの ADR） | 単一行の文字編集 + IME + 書き戻し |
| 項目を改名 | 項目行の「…」→ 改名ダイアログ → Save | 閉じ込め × 最前面層 × 文字入力 × IME |
| 項目を保管（Archive） | 項目行の「…」→ Archive（確認ダイアログを出さない） | 最前面層の閉じ方 + 書き戻し |
| リストを開く | 一覧ウィンドウの行クリック / Open | 複数ウィンドウ（新規に開く、または既存ウィンドウへフォーカスを移す） |
| リストを作る | 「＋ 新しいリスト」→ **自動命名**でウィンドウを即作成 | 複数ウィンドウ。根から開く名前入力ダイアログを持ち込まない（根宣言のダイアログは ZStack で足りてしまい、閉じ込め × 最前面層の組合せを実証しない） |
| リストを改名 | 一覧ウィンドウの行の「…」→ 改名 | 動的タイトル（改名がタイトルに出る）+ 書き戻し |
| メニュー / ダイアログを閉じる | 外側クリック / Esc / Cancel | 最前面層の規則一式（閉じ方・フォーカスの戻し・読み上げ順序） |

### データ形状

各リストの項目は**文字列の並び**である。項目ごとの状態・色・日時・
担当者を持たない。リスト自身は名前を持ち、件数は項目の並びから導く。

### B4 の 2 つの上限（採択理由を守る制約）

以下は「守れば安い」ではなく「**破ると採択理由そのものが失われる**」
制約であり、アプリ仕様として固定する
（[framing.md](framing.md) §第二アプリの採択に依存して変わるもの）。

1. **項目は文字列の並びに留める。** 項目ごとの状態・色・日時・担当者を
   持たない。破ると `TypedValue` / 構造化された項目データの保留に触れ、
   チャット案に対する優位（構造リスクの低さ）が消える。完了・優先度・
   期限を入れない（Todo アプリに寄せない）のはこの上限の帰結であり、
   CheckBox / Toggle も使わない。
2. **一覧ウィンドウの行に件数を出さない。** 行はリスト名のみ。件数を
   出すと、あるリストウィンドウでの追加が別ウィンドウ（一覧）の表示へ
   波及し、A が担う「表示中のホスト書き込み（差し替え）」を B4 が重ねて
   要求してしまう。**ウィンドウのタイトルとステータスバーの件数は上限を
   破らない** — そのウィンドウ自身の操作でのみ変わるため。

### B4 が持たないもの

- **複数行の文字編集** — 項目は短い一行の思いつきに留める。
- **完了状態 / チェックボックス / 並べ替え / ドラッグ** — 上限 1 と
  M4 の範囲外（公式部品一式は M5）。
- **部品への吸着（アンカー付きの小窓）** — メニューの配置は粗い手動で
  よい。宣言的な吸着は M4 に含めない（[候補プール](../../candidate-pool.md)
  に記録済み、正規の買い手は M5 の部品一式）。
- **削除の確認ダイアログ** — Archive はメニューから直接実行する。
  閉じ込め × 最前面層の実証は改名ダイアログが担うため、確認ダイアログを
  重ねて持つ必要がない。

## M4 が開く機能面

2 本のアプリから逆算した、M4 で開く機能面の一覧。「層」列は
[framing.md](framing.md) §二層取り込み方針の区分:
**AC** = 既存の達成条件、**中核** = AC へ昇格する取り込み（§ROADMAP
達成条件との同期）、**予備** = 題材アプリの機能（AC 非昇格）、
**上積み** = AC の解釈の上積み。

### 入力・フォーカス（runtime 中核）

| 機能面 | 層 | 役割 | 検証する主眼 |
|---|---|---|---|
| フォーカスモデル + イベント配送 | AC | フォーカスの所在・移動・イベントの経路を一度で決める | M4 主眼そのもの。「入力・複数ウィンドウ・文字入力・アクセシビリティが同一のフォーカスモデルを共有する」ことの証明 |
| モーダルなフォーカス範囲 | AC（フォーカスモデルの一部） | 任意の部分木に付けられる閉じ込め。層の性質としてではなく構造非依存の概念として定義する | ZStack の枝（A のライトボックス）と最前面層の中身（B4 の改名ダイアログ）という**2 つの構造**が同じ概念の消費者になること |
| 汎用クリック処理 | AC の具体化 | Button 以外の部品へのヒットハンドラ。項目ごとのハンドラ（item / index 参照）と ZStack 兄弟間の遮蔽規則を含む | 既存の `Button.clicked` と汎用のクリック処理が同じ配送モデルの上に載ること |
| 入力処理（キーボード / マウス / タッチ） | AC | 生の入力をフォーカスモデルへ供給する | 入力の 3 経路が同一のフォーカスモデルに合流すること |
| フォーカス意味論の機構検証 | AC 相当（アプリ非依存） | M5 の公式部品一式が要求する意味論（グループ内の矢印キー移動 / フォーカスと活性項目の分離）を、部品を作らずに固定する。走査の中核を Win32 非依存の純ロジックとして単体テスト + 最小 fixture | 主眼「フォーカスモデルの一回確定」が M5 の部品実装で破れないこと |

### 文字編集（B4）

| 機能面 | 層 | 役割 | 検証する主眼 |
|---|---|---|---|

## 範囲外（アプリ仕様の面から）

M4 全体の範囲外は [framing.md](framing.md) §M4 に入れないもの が正本。
ここではワイヤーフレーム上に見えるが**アプリ仕様として扱わない**もの
を固定する。

### 見た目・装飾

- **全面的なテーマ対応**（明暗テーマ、アクセント色の部品への伝播、
  文字の大きさ体系）— M5。M4 はルートの背景材 + アクセント色追従まで。
- **仕上げの細部** — 影・角丸・余白の詰め・アニメーション。見本アプリの
  達成条件は仕上げ細部の粗さを許容する。
- **メニュー / ダイアログの吸着配置** — 粗い手動配置でよい。

### 操作

- **元に戻す（undo / redo）** — 入力欄に持たせない（TSF の技術要件では
  なく製品期待。M5 以降）。
- **パスワード用の伏せ字・装飾つきテキスト** — 入力欄に持たせない。
- **並べ替え / ドラッグ操作 / 範囲の複数選択** — 2 本のアプリとも
  要求しない。
- **検索 / 絞り込み** — A は検索欄を持たない（§A が持たないもの）。
- **キーボードショートカットの体系** — Esc・Tab・← → ・Ctrl+C/X/V など
  各機能面が要求するものに限る。アプリ独自の割り当ては持たない。

### データ・型

- **`TypedValue` / 構造化された項目データ** — 保留。B4 の上限 1 は
  この保留を破らないための制約である。
- **文字列連結 / 算術を含む式** — M4 の式言語は述語まで。件数表示は
  静的 Text と束縛の並置で書く。
- **永続化の形式** — ホスト側の関心事であり、DSL / ランタイムの仕様
  ではない。ホスト状態境界の往復が成立すればよい。

### 部品

- **公式の部品一式**（CheckBox / ComboBox / Menu ほか）— M5。B4 の
  メニュー・ダイアログは既存部品（Box / Text / Button / 入力欄）の
  **作者合成**であり、`Menu` / `Dialog` という公式部品は作らない。
- **フォーカス意味論の機構検証に使う fixture** — 公式部品として公開
  しない（`spec.md`・部品一覧に載せず、綴りは fixture 限定の非規範）。
  仮の RadioButton / ComboBox を部品として作ることはしない。

## 仕様 / 実装 / 見本アプリの同期ルール

M3 の同期規律（同一フェーズ内で `.ui` → IR → ランタイム →
`docs/dsl_spec.md` を揃える）を M4 でも維持する。2 本立てに伴う追加:

- **アプリは達成条件の判定基準として機能する。** 各フェーズの完了判定
  で、そのフェーズが開いた機能面を A または B4 の実画面が実際に通る
  最小ケースとして置く。どちらのアプリが判定基準になるかは
  §2 本の役割分担の担当に従う。
- **2 本は同時に完成しない。** A が初期フェーズ、B4 が後段フェーズの
  消費者という時間差の並びを前提とする。B4 は M3 資産（ScrollView・
  繰り返し生成・Box / Text / Button）の上に一行の入力欄と最前面層を
  足す形のため、A の初期フェーズが固めた土台をそのまま踏める。
- **規範スペックの執筆は後回しにしない。** 新しい文法面（入力欄・
  最前面層・ウィンドウ設定プロパティ・述語式・項目ごとのハンドラ）は
  それを開いたフェーズの完了時点で `docs/dsl_spec.md` に反映済みで
  あることを要求する。ABI に影響するホスト状態境界は
  `docs/abi_spec.md` も同様。
- **視覚の証拠**は、A = M3 の
  [gallery-wireframe.html](../../milestone-3/requirements/gallery-wireframe.html)、
  B4 = [候補節](target-app-wireframes.additional.html) を参照して判定
  する（→ §視覚資料との参照関係）。
