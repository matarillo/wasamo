# T4 レトロスペクティブ

タスクブランチ: `feat/m4-phase-2-t4`（`feat/m4-phase-2` = `c9a00d0` から作成）

hover / pressed を「木全体を歩いて、自分の矩形に点が入っている Button 族
すべてに状態を書く」から「解決した唯一の対象に対する enter / leave」へ

誰も気づかないことだった** — hover に触れるテストが repo に 1 本も存在
しなかった。

T10 まで occlusion は観測できない」は偽である。ライトボックスは今日
開閉でき、その scrim は client 全面を覆う。pre-T4 のビルドで、scrim 越しに
ツールバーの `ToggleButton` が hover 色に入っていることを測った。

### 観測された事実（反証可能な signal）

- **hover に触れるテストがゼロだった。** T1〜T3 は「既存 suite が緑」を
  regression check として使ってきたが、T4 の対象領域には regression の
  対象そのものが存在しなかった。「緑は正しさの証拠ではない」という
  preamble の一般命題の、最も強い形が出た。
- **plan の T4 節の evidence 欄は統合テストしか求めていなかった。**
  GUI 陽性対照は plan にも preamble の lane 表にもない。しかし実測では
  5 分で構築でき、pre-T4 に +5.76 / +3.90 / +2.89、post-T4 に
  0.00 / 0.00 / 0.00 という判別を出した。
- **phase 文書の否定的予測が偽だった。** 「T10 まで occlusion は観測
  できない」は hover 側でも click 側でも偽で、3 task に読まれたまま
  一度も再測されていなかった。
- **変異証人 7 本のうち、fixture の判別力を測れたのは W7 の 1 本だけ。**

### 自己分析（どの層が外れたか）

外れたのは **phase 側の「証拠が構築できるか」の予測**と、**lead の
fixture 受け入れ判定の方法**の 2 層。

T3 retro が入れた是正線は「*次の task に要求する* evidence が構築
可能か、1 回作って走らせたか」だった。今回顕在化したのは**向きが逆の
穴**である ——「phase が『構築**不能**』と予測した evidence が、本当に
構築不能か」。肯定的な要求は「作れませんでした」で必ず露見するが、
否定的な予測は誰も測らないので**そのまま生き延びる**。T2 は「gallery
フレームは判別しない」を前提に証拠を設計し、T3 は同じ文を読んで罠 #7 を
非該当にした。どちらも結論自体は妥当だったが、根拠は未検証の予測
だった。

もう 1 層は受け入れ判定。fixture の**判別力は読解では測れない**。F5 は
文章として完璧で、間違っていたのは座標 1 行だった。読解でこれを捕まえる
には、レビュー時に自分で幾何を再計算する必要がある —— それは実質、
変異を走らせるより高くつく。

### 計画仮説・前提の問い直し（オーナーと）

- **phase 文書の否定的予測（「〜は観測できない」「〜は証拠にならない」）
  は、それに依存する最初の task の start gate で 1 回測る。** T3 の
  是正（肯定的な evidence 要求を先に構築する）と対称に扱う。今回の
  コストは 5 分だった。
- **変異証人には「修正前の挙動を復元する 1 本」を必ず含める。** 実装の
  変異は「テストが自分の実装を見ている」ことしか示さない。復元変異
  だけが「このテスト群は元の欠陥を捕まえるか」に答える。
- **subagent が書いた fixture は、読解ではなく変異で受け入れ判定する。**
  今回 5 本中 1 本が非判別で、それはレビューの読解を通過していた。

### 反証可能な是正テスト

以後の task の **close gate に 1 行**の判定を足す（T1 の「新しい store /
単位 / 座標系」、T2 の「消す性質を pin しているテスト」、T3 の「次の task に
要求する evidence を 1 回構築したか」に並べる）:
「変異証人に**修正前の挙動を復元する 1 本**が含まれているか。含まれない
なら、この task の fixture が元の欠陥を捕まえるという証拠はない。」
反証条件は明確で、以後の task で「実装は正しかったが fixture が非判別
だった」が見つかったら、この是正は効いていない。

もう 1 つ、**start gate に 1 行**:「この task が依拠する phase 文書の
**否定的予測**はどれか。1 回測ったか。」反証条件は、phase 文書の否定的
予測が後の task で偽と判明したら効いていない。
