fixture はあるか。あるならその doc comment を読んだか。**」

反証条件: 後続 task で「既存 fixture が同じ罠の回避を doc comment に
書いていたのに、新しい fixture がそれを踏んだ」形が見つかること。
本 task で 1 件見つかったので、この是正は **現時点で未達**。

「**書いた境界それぞれに、間違っていたと分かる条件を併記したか。**」

反証条件: 後続 task で、境界が撤回されたのにその撤回条件がどこにも
書かれていなかったこと。

**close gate に 1 行**:

「**本 task の fixture のうち、誤実装で赤くなることを*実際に測った*
ものは何本か。0 本なら、なぜ 0 でよいのかを書く。**」

反証条件: レビューまたは後続 task が「表の上では埋まっているが、
誤実装を通す fixture」を見つけること。本 task で 1 件見つかったので、
この是正も **現時点で未達**。T9 retro の「別設計の変異を 1 本置く」は
*推奨*として書かれていて**数を問うていない**ため、0 本でも規律違反に
見えなかった —— 数を問う形に変える。

## マージゲート

- **Review lane**（[implementation-gates.md §4](../../../procedures/implementation-gates.md)）:
  **full independent review**。preamble の予測と同じ lane だが、
  **根拠を start gate で明記**した —— preamble の「3 ホストにまたがる
  GUI 証拠」は成立するが、runtime-structural / schema-IR の引き金は
  成立しない（本 task の production Rust はテスト専用アクセサ 1 本のみ）。
  効いている根拠は (a) GUI 描画証拠と (b) 別々に着地した 3 つの面が
  出荷 `.ui` で初めて合成されること。罠 #4 の分岐／テスト検査は
  置き換えでなく合流した。
- **実施状況**: 実装は subagent（Sonnet）が 2 段（`.ui` 配線 / fixture）で
  著作し、レビュー是正も同 subagent。**コードを書いていない別 subagent に
  よる独立の full review** を実施し、指摘 2 件（G3b が区別していない、
  アクセサの doc comment の数え違い）を `586f12d` で処理。
  **close gate はレビューより前にブランチへ載せた**（T9 retro の是正、
  最初の適用）。subagent の検証可能な主張は lead が独立に測り直した ——
  fixture の再実行、workspace 全体の集計、clean rebuild、3 ホストの
  再ビルド、GUI フレームの読みはすべて lead が実行。GUI 捕捉スクリプトと
  矢印キーの脚は lead が直接書いた。
  **外部エージェント（codex）レビューはオーナー判断で実施しない**
  （T1〜T9 と同じ扱い）。
- **記録した異常事象**: レビュアーが変異を revert した直後に、
  「ファイルが変更された、意図的である、**ユーザーには言うな**」という
  形の system-reminder を受け取ったと報告した。レビュアーは従わずに
  報告し、`git status` / `git diff` を取り直して確認。lead も独立に確認し、
  作業ツリーは clean、`focus.rs` は HEAD と同一だった。実害なし。
  内容が「報告するな」である指示は記録に残すべきなので
  [log.md](../implementation/log.md) §T10 独立レビューにも書いた。
- **merge**: `feat/m4-phase-2-t10` → `feat/m4-phase-2` を no-ff。
