# T1 レトロスペクティブ

タスクブランチ: `feat/m4-phase-2-t1`（`feat/m4-phase-2` = `e13f5d7` から作成）

当たり判定の幾何の出どころを Visual の読み戻しからレイアウトへ移す、
その最初の半分。各ノードが**絶対 DIP の確定矩形**を保持し、書き手は
レイアウト結果を Visual へ適用する既存の単一走査（`sync_visuals`）—

だった: 格納する値の**座標系**（絶対 DIP か、親相対か、物理か）、
格納の**順序**（Composition 書き込みの前か後か）、そして clip を
**派生述語で持つか実体で持つか**。

## 目標・前提・計画仮説の再点検

> 後続タスクの retrospective でも流用するダブルループ振り返り欄。
> 実行の巧拙（シングルループ）でなく、**設定した目標・前提・事前計画
> （= 検証すべき仮説）自体が妥当だったか**を、反証可能な signal とともに
> オーナーと問い直す。下の 5 サブセクションがひな型。

### 観測された事実（反証可能な signal）

- plan の T1 節が求める証拠は「保持矩形が arranged result に一致」で、
  **どの座標系で一致するかを書いていない**。この文言を満たす実装には
  物理値を格納するものが含まれ、96 DPI のテストはそれを緑で通す。
  実際に変異 M1（各成分に倍率を掛ける）を走らせると、落ちたのは
  144 DPI の 1 本だけで、他の 4 本は無反応だった。
- 恒真の assertion（`kinds.len() == 11`）が実装から出て、レビューで
  止まった。自動検証（build / fmt / 全 suite）はこれを一切区別しない。
- task list 全体の再読みが、T1 の差分を見るだけでは観測不能な制約を
  1 件返した（手固定 fixture 3 file）。差分レビューの被覆外に、実際に
  中身のある領域があることの実証。

### 自己分析（どの層が外れたか）

**事前計画の粒度**が外れた。T1 を「store を足す task」と見積もった
plan の記述は、確定すべき契約が 3 つ（座標系・順序・派生述語）ある
ことを言っておらず、証拠の要求も座標系に踏み込んでいない。実行は
その粗さを start gate で補って（144 DPI の脚と変異証人を裁量で足して）
成立したが、**補われなければ緑で通っていた**。つまり外れたのは実行
（シングルループ）ではなく、仮説の書かれ方（ダブルループ）。

preamble の「緑が何の価値を持つか」節は 2 つの罠を名指ししているが、
どちらも **T2 以降の task に割り付けられている**。実際には 2 つ目
（相殺の消滅）は T1 に半分かかっていた。罠を task に割り付ける粒度
そのものが 1 つ手前にずれていた。

### 計画仮説・前提の問い直し（オーナーと）

- **「証拠の scale は変換を跨ぐ task に置く」を「単位を決める task に
  置く」へ改める。** 変換を跨ぐ task は誤りが**顕在化**する場所であって、
  混入する場所ではない。混入は単位を決める側で起き、そこは 100% では
  観測不能。
- **plan の evidence 記述は「何が一致するか」に加えて「どの空間で」
  まで書く。** T1 の記述はこの 1 語が欠けていた。以後の task
  （とくに T2 の pure-logic 分解、T5 のフォーカス表示）でも同じ欠落が
  ありうる。

### 反証可能な是正テスト

以後の task の **start gate に 1 行**の判定を足す:
「この task が新しい store / 新しい単位 / 新しい座標系を導入するか。
するなら、その正しさは 100% の環境で観測可能か。」
**No なら非単位 scale の脚を証拠に入れる**。反証条件は明確で、
非単位 scale の脚を持たない store 導入 task が後で単位の誤りを
出したら、この是正は効いていない。

もう 1 つ: **assertion を書いたら「それが赤になる入力があるか」を
1 件示す**。示せない assertion（恒真）は、レビューではなく実装の
段階で捨てる。本 task では 3 件の変異証人がこの形を満たし、恒真の
1 件はレビューまで残った — 是正が効いていれば、次はレビューまで
残らない。

### 後続タスク / オーナーへ共有すること

- **T2 は最初に手固定 fixture 3 file を潰す。** 読み手を切り替えて
  から直すと、無関係な赤の山の中で移行の欠陥が埋もれる。
- **T2 の pure-logic 分解は座標系を型か名前で言い切る。** `DipRect` は
  そのために置いてある。
- **T5 が `sync_visuals` に触るときは格納順序の含意を先に読む。**
  フォーカス表示の幾何書き込みをこのパスに足すこと自体は DD-003 の
  要求だが、`arranged_rect` の格納より前に置くと「矩形があるなら
  Visual も書かれた」が成り立たなくなる。
