### 観測された事実（反証可能な signal）

- T13 は実測の集積を re-verify する doc-only close と見積もり、Normal lane
  を選んだ。しかし required cold suite が、既存 test の allocator reuse
  branch を初めて発火させ、runtime invariant を falsify した。
- 同じ binary で non-reuse は 2/2 pass、reuse は 2/2 同一 failure。これは
  retry-to-green flake ではなく、到達条件だけが確率的な deterministic defect。
- 修正後は forced-state fixture が repair 無しで必ず赤、repair 有りで必ず緑。
- task branch CI は全 step green だが、branch name は phase procedure item 16
  の ground truth ではない。

### 自己分析（どの層が外れたか）

外れたのは T13 再検証一覧の中身ではなく、**close gate は新しい実装事実を
発見しない**という暗黙の見積もりだった。carry-forward の re-trigger を
suite に残したこと自体は正しく、そのため計画の境界が反証された。発火後に
Normal lane を維持せず full independent review へ訂正できた点は gate が
機能した結果である。

統合順序も同じで、task branch を phase close の最終 branch とみなした記録は、
実際の no-ff target が決まった時点で前提が外れた。phase close は merge 後に
改めて行う必要がある。

### 計画仮説・前提の問い直し（オーナーと）

runtime repair の判断限界では、identity redesign と narrow reconciliation
のどちらを選ぶかをオーナーに問い、後者だけが承認された。完了時には統合順序
をオーナーが「task → phase no-ff、その後 phase close」と確定した。どちらも
黙って既成事実にせず、plan / log / retrospective の ownership を訂正する。

### 反証可能な是正テスト

- close residual の natural observer は残し、発火したら同じ state を強制する
  deterministic gate を追加する。repair call 除去で赤にならなければ是正失敗。
- final task が作業 branch を持つ phase では、task retro / no-ff merge の後に
  phase branch SHA を dispatch する。別 branch の run id しか無ければ phase
  item 16 は未達と判定する。

### 後続タスク / オーナーへ共有すること

- CF-T7-1 / CF-T9-1 は全閉鎖ではない。presentation inconsistency だけが修復
  済みで、same-address fresh node が unexpected focus target になる identity
  remainder は残る。
- CF-T12-5 は義務化の決定ではなく、Phase 3 pre-doc で開く問いのまま。
- phase branch push、phase-branch CI、phase-to-`main` merge はそれぞれ別 gate。
