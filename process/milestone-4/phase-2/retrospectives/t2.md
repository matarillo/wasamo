# T2 レトロスペクティブ

タスクブランチ: `feat/m4-phase-2-t2`（`feat/m4-phase-2` = `a7bb771` から作成）

当たり判定の幾何の出どころを Visual の読み戻しからレイアウトへ移す、
その後ろ半分。読み手 2 つ（`hit_test_click` と `update_hover`）を同一
コミットで切り替え、走査を「含む Button を全部撃つ」から「最上位の
1 つに解決する」へ変えた。解決は純ロジックの自由関数（矩形 + 順序 +
clip 境界 → 対象）で、Compositor なしで単体テストできる。

見た目は「読み手の付け替え」だが、実際に効いたのは移行そのものより
**旧性質を pin していたテストの棚卸し**だった。plan が名指ししていた
3 file に対し、実測は 5 file。増えた 2 file は移行後も**緑のまま**で、
片方は理由書きだけが嘘になる形だった。

### 観測された事実（反証可能な signal）

- **変換欠落の変異（W1）で赤になったのは、workspace 全体で 1 本だけ**
  だった。Phase 1 が「行 9 の欠落を試験で区別できない」と記録した性質が、
  T2 で「ちょうど 1 本が区別する」に変わったことの実測。他の全テストは
  倍率 1 で走るので無反応であり、これは preamble が予告したとおりの形。
- **plan の「手固定 fixture 3 file」は実測 5 file**。増えた 2 file は
  移行後も緑で、うち 1 file は理由書きだけが偽になる。差分レビューでも
  自動検証でも区別されない領域が、T1 に続いて再び 1 件出た。
- **合成 `SendMessageW` のクリックは再レイアウトを起こさない**。plan の
  staleness 項の文（「property 書き込みが再レイアウトを起こす」）は
  production では正しいが、fixture の駆動方法としては成立しなかった。
- **変異証人が「適用されないまま緑」になりかけた**（学び (a)）。

### 自己分析（どの層が外れたか）

外れたのは**事前計画の射程**。T2 節は「読み手を切り替える」「手固定
fixture を潰す」までは書いていたが、次の 2 つを書いていない:

1. **消す性質を pin しているテストの棚卸し。** 移行で壊れるテストは
   赤くなるので必ず見つかる。危ないのは反対側 — 消えた性質を pin して
   いたのに、新しい実装でもたまたま緑になるテスト。これは実装事実を
   見に行かない限り出てこない。
2. **production のどの関数がその段を呼ぶか。** 「property 書き込み →
   再レイアウト」は production の性質としては正しく、fixture の設計
   前提としては誤りだった。**性質が真であることと、テストからその経路に
   入れることは別**。

T1 の学びは「証拠の scale は、変換を跨ぐ task ではなく**単位を決める**
task に置く」だった。今回はその同型で、「証拠の**意味**は、旧性質を
**消す** task が引き取る」。どちらも、plan が task に割り付けた粒度が
1 つずれていたという同じ層の話であり、実行（シングルループ）の巧拙では
ない。

### 計画仮説・前提の問い直し（オーナーと）

- **移行的な task の plan 記述に「旧性質を pin しているテストの棚卸し」を
  明示項目として入れる。** 「読み手を切り替える」だけでは、赤で気づける
  側しか計画に入らない。T2 では start gate でこれを補ったが、補われ
  なければ緑のまま偽の理由が残っていた。
- **fixture の駆動経路は、性質の真偽とは別に測る。** 「合成メッセージで
  production の段が回る」を前提に置かない。T3 / T4 / T8 / T9 / T11 は
  全部クリック fixture を書くので、この前提は繰り返し効く。

### 反証可能な是正テスト

以後の task の **start gate に 1 行**の判定を足す（T1 の「新しい store /
単位 / 座標系を導入するか」に並べる）:
「この task が**消す**性質を pin しているテストはどれか。移行後、それは
**赤くなる**か、**緑のまま理由が嘘になる**か。」
反証条件は明確で、この棚卸しをした task の後に「理由が嘘のまま緑の
テスト」が見つかったら、この是正は効いていない。

もう 1 つ: **変異証人は、変異がファイルに入っていることを読み戻して
から走らせる。** 反証条件は、読み戻しなしの証人が再び偽の緑を出したら
効いていない。
