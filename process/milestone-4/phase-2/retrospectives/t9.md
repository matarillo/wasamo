# T9 レトロスペクティブ

タスクブランチ: `feat/m4-phase-2-t9`（`feat/m4-phase-2` = `af62fd8` から作成）

`for` 本体の中に `signal_handler` を書けるようにし、その本体で
`item` / `index` を**ハンドラが走る時点で**解決するところまで通した。
M3-Phase 7 が「4 つの答えを一緒に決めるまで」と先送りした面が閉じた。

plan の T9 は本 task を「フェーズ唯一の新しい IR 内容（ハンドラ本体へ
持ち込む loop scope）＝ schema / IR クラス」と framing していたが、
**着手前の実測でその前提は崩れた**。`lower` は既に loop context を
ハンドラ本体へ渡しており、`ItemRead` / `IndexRead` は既に存在し、
`emit` は既に書き出し、IR テキストの s 式パーサは bind と handler で
共有されている。**IR 型・文法・lowering の変更はゼロ**。残っていたのは
DD-M4-P2-005 が並べて書いているもう半分 —— 実行時の評価コンテキスト
だけだった。review lane は着手前に訂正した（schema/IR ではなく
**実行時の構造変更**を根拠に、full independent review のまま）。

### 自己分析（どの層が外れたか）

外れた層の 1 つめは **subagent への brief の粒度**である。私は
「per-item handler の binder read を評価できるようにせよ」と書き、
「3 つの要素型がそれぞれ別の評価関数を通る」ことを書かなかった。
着手前の私自身の調査は `evaluate` の `ItemRead` 拒否まで到達しており、
`evaluate_binding` / `evaluate_bool_assignment_value` を読んでいれば
同じ日に見えていた。**start gate の「実測」は自分が次に何を作るかの
範囲で止まりやすく、「その面の全部の経路」まで届かない。**
T8 の学びを「到達経路の数」から「面の分割軸の数」へ広げる必要がある。

2 つめは **close gate とレビューの順序**である。順序を崩したのは
意図的で、理由は「レビュアーに私の説明を読ませない方が独立性が高い」
だった。これは半分正しく、半分は自己都合である。独立性は保てたが、
implementation-gates が close gate に artifact を要求している目的は
**レビュアーが ground truth と照合できること**であり、再構成させた分は
純粋なコストだった。しかも finding 3 として指摘されるまで、私は
これをトレードオフとして意識していなかった —— つまり判断ではなく
段取りの都合だった。

3 つめは **「レビューが毎回穴を見つける」ことの扱い**である。4 task
連続という事実を T8 retro が記録し、T9 でも再発した。個々の穴は
毎回違う場所だが、**共通しているのは「lead が close gate を書き終える
前後で、branch table が diff から作り直されていない」**ことである。
今回も branch table は close gate を書く段階で作り、その時点で
`bool[]` の `None` 腕は表に載っていなかった。表を diff から機械的に

### 計画仮説・前提の問い直し（オーナーと）

- **preamble の review lane 表は「lane」だけでなく「根拠」を書くべき
  ではないか。** T8 と T9 は連続して「lane は合っているが根拠が違う」形で
  ずれた。根拠が違うと、start gate で lane を再判定するときに
  「変える必要なし」と読み飛ばす誘因が働く。表に根拠列があれば、
  根拠の変化が lane の変化と同じ強さで目に入る。
- **close gate はレビューの前に書く、を明示規律にすべきか。**
  implementation-gates §0 は順序を書いているが、逆順にした場合に
  何が失われるかは書いていない。今回の実測では「レビュアーが artifact を
  再構成する分のコスト」が失われた分で、独立性の利得は
  （レビュアーが artifact を読んでも独立に測り直す運用なので）ほぼ無い。
  逆順を禁止するか、逆順にするなら理由を start gate に書かせるか。
- **subagent brief に「この面はいくつの経路／型／種別に分かれるか」を
  1 行足すべきではないか。** T8 は「到達経路は 1 本か」を close gate の
  是正にした。T9 が踏んだのはその型軸版で、**brief を書く時点**で
  効かせないと subagent は自分の brief の外を見ない。

### 反証可能な是正テスト
