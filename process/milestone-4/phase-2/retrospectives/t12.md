## 目標・前提・計画仮説の再点検

> 後続タスクの retrospective でも流用するダブルループ振り返り欄。
> 実行の巧拙（シングルループ）でなく、**設定した目標・前提・事前計画
> （= 検証すべき仮説）自体が妥当だったか**を、反証可能な signal とともに
> オーナーと問い直す。下の 5 サブセクションがひな型。

### 観測された事実（反証可能な signal）

- plan の T12 項目は 4 つの対照について difference 脚と agreement 脚を
  書いている。**「その脚が赤になりうることをどう示すか」は書いていない。**
  実測: 37 verdict 中 13 本が区別能力を持たず、1 本も緑の実行では見えな
  かった。
- そのうち 2 本を捕まえたのは、plan ではなく **start gate で項目本文を
  超えて足した 2 つの読み**だった。足せたのは T11 の retrospective を
  読んでいたからで、plan 側には手掛かりが無い。
- **残り 11 本は、その読みの射程の外にあった。** 足した規律は「脚が赤に
  なりうるか」を要求しており、「**脚を判定する帯がどう作られているか**」は
  要求していなかった。帯の定義は脚のテキストからは見えず、帯の定義と脚を
  並べて読んだときだけ現れる。
- 同じ形が phase 内で 3 度目である（T11 の学び (c)、本 task の 2 本、

### 自己分析（どの層が外れたか）

外れたのは**実行**ではなく**計画の見積もり層**で、しかも 2 段階ある。

1 段目: 「証拠を撮る task」を機構作業（捕捉・比較・記録）と見積もり、
**校正作業**として見積もっていなかった。この見積もりは plan の項目
テキストにそのまま現れていて、項目は*何を撮るか*を精密に書き、*撮った
ものが何と区別できるか*を脚の名前以上には書いていない。

2 段目のほうが重い: 是正として start gate で足した規律も、**私が想像
できた失敗の形（脚が甘い）に沿って armed されていた**。実際の失敗は
一段メタで、判定基準そのものが循環していた。自己点検は「自分が想像
できる失敗」しか armed できないという構造的な限界がそのまま出ている。
`implementation-gates.md` §3 が「新種の罠は自己点検では捕まえられない
ので §4 のレビューと §5 の学習ループが backstop」と書いているとおりの
事例で、**backstop が実際に機能した**。

DD-V-029 は純ロジックの丸め・単位変換・境界条件について red-test 義務を
narrow scope で持つが、**捕捉スクリプトの verdict はその scope の外**で
ある。13 本すべてがその外側で起きた。

### 計画仮説・前提の問い直し（オーナーと）

**問い 1: 陽性対照を要求する plan 項目に、「この脚が赤になりうることを
どう示すか」を項目の時点で書かせるべきか。**
今回は start gate で足して 2 本には間に合ったが、それは前 task の
retrospective を読んだ人がいたからで、規律ではなく偶然に近い。項目は
1 行増える代わりに、区別能力の無い脚が計画の時点で見えるようになる。

**問い 2: DD-V-029 の red-test 義務を、捕捉スクリプトの verdict まで
広げるか。** 広げるなら vision decision record（構造的変更）であり、
広げないなら「判断で担保する」ことを明示的に選ぶことになる。どちらでも
よいが、**黙って scope 外のままにするのが今回の失敗の形**だった。

**どちらの問いも、11 本のほうは解決しない**ことは正直に言っておきたい。
帯の循環は「脚に red-test を課す」規律の射程外だった。11 本に効いたのは
独立レビューであり、そこから引ける教訓は「**自己点検の armed 範囲を
広げる**」ではなく「**独立レビューを削らない**」のほうかもしれない。
その判断はオーナーのものとして残す。

### 反証可能な是正テスト

次に陽性対照を撮る task —— 最初の候補は **M4-Phase 4 のスクロール証拠**
—— で測れる:

- その task の plan 項目に、脚の一覧と並べて「self-check をどう組むか」を
  **最初から**書く。
- 加えて、self-check の網羅を**スクリプト自身に検査させる**（本 task の
  `-Compare` が verdict を登録し `-SelfCheck` が穴で落ちる形）。これは
  今回の 11 本を捕まえられた唯一の機構的な手当てである。
- 反証条件をはっきりさせておく: **「self-check を最初から書き、網羅を
  スクリプトに検査させた task で、なお区別能力の無い脚が 1 本でも出たら、
  この是正は失敗」。** 出なかった場合も、独立レビューが別の類型を見つけた
  なら、是正は「十分」ではなく「必要条件のひとつ」と記録する。

### 後続タスク / オーナーへ共有すること

- **CF-T12-1**（半透明の覆いと閾値）は M4-Phase 9 が最初に踏む。
- **CF-T12-2**（帯まで含めた red-test 規律と、網羅の機械検査）は、比較
  スクリプトを書くすべての後続 task に効く。
- 上の 2 つの問い —— plan 項目に self-check を書かせるか、DD-V-029 の
  scope を広げるか —— は**オーナーの判断**であり、この task の close gate
  からは決めない。
- **独立レビューの費用対効果について 1 つの実測**: 本 task では
  レビューが 14 件を返し、うち 1 件は 2 つのゲートのどちらも構造的に
  捕まえられない類型だった。lane を「full independent review」に置いた
  判断は、この 1 件だけで元が取れている。
